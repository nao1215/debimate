パーセプトロン（perceptron）は、入力の各列に重みを掛けて足し、その符号で 2 つの分類のどちらかを答えるモデルです。学習では、学習データを 1 行ずつ予測し、誤った行の入力を重みに足すか引くだけです。1958 年に [Rosenblatt 氏が発表](https://doi.org/10.1037/h0042519)したもので、今のニューラルネットワークを組み立てるユニットの原型になりました。Samsung が自社で設計した Exynos のコアなど、一部の CPU では、条件分岐がどちらへ進むかを当てる回路にも使われてきました。

重みに足す量には、学習率という倍率を掛けます。[scikit-learn](https://scikit-learn.org/stable/) の [`Perceptron`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Perceptron.html) では `eta0` という引数です。[勾配降下法](../../math/gradient-descent-sgd/)では、学習率が大きすぎると発散し、小さすぎると進まないので、`eta0` も調整したくなります。では、`eta0` はパーセプトロンの何を変えるのでしょうか。

scikit-learn に同梱の [breast_cancer](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_breast_cancer.html) は、乳がんの腫瘍 569 個を 30 列の値で測り、悪性か良性かを付けたデータです。これを学習 426 行とテスト 143 行に分け、`eta0` を 1e-6 から 1e6 まで 7 通りに変えて、学習データを 50 周させました。途中で止める仕組みは `tol=None` で切ってあり、どの `eta0` でもちょうど 50 周です。

{{< figure src="pc_cover.webp" alt="止める仕組みを切って 50 エポック回した結果。左は 7 本の横長の帯で、上から eta0 が 1e-6、0.0001、0.01、1、100、10000、1e6 の時のテスト 143 行の予測を並べたもの。どの帯もテストの元の順に赤（悪性）と青（良性）が縞に並び、7 本とも同じ並び。右は重みの長さの横棒で、eta0 に比例して 6e-05 から 6e+07 まで 12 桁伸びる" caption="止める仕組みを切って 50 周させた時の、eta0 ごとのテストの予測（左）と重みの長さ（右）" align="center" >}}

重みの長さは `eta0` に比例して 12 桁伸びましたが、テスト 143 行の予測は 7 通りとも全て一致しました。正解率はどれも 0.958 です。

これは、`Perceptron` の既定どおり重みを 0 から始め、正則化を掛けず、周回の数をそろえた時の結果です。止める仕組みが働く既定の設定では、`eta0` は学習データを何周した所で止まるかを変え、それを通して予測を変えます。[ハイパーパラメータ](../hyperparameter/)の探索で `eta0` の候補を並べて正解率が動いた時は、線の向きが良くなったのではなく、止まる周回が変わった可能性があります。

<br>

本記事では、パーセプトロンを ML の入門で学ぶ人と、scikit-learn の `Perceptron` を手元のデータで使う人に向けて、次の疑問に答えます。

- パーセプトロンは、誤った時に重みをどう直すのか。
- 学習率を変えても、なぜ予測が変わらない場合があるのか。
- 線で分けられるデータなら、何回の更新で止まるのか。
- scikit-learn の `Perceptron` は、どこで止まり、止まった時の線はどうなるのか。
- ロジスティック回帰や SVM（サポートベクターマシン）と、線はどう違うのか。
- 線で分けられない時、CPU の分岐予測では何が起きるのか。

実験は scikit-learn 1.9.1 と NumPy 2.5.4 で行いました。図を描く処理も含めた完全なコードは [perceptron_gen.py](https://github.com/nao1215/debimate/blob/main/projects/ml/scripts/notes/perceptron_gen.py) にあります。

### 誤りのたびに足す学習

1 行の入力をベクトル `x`、重みを同じ長さのベクトル `w`、切片を `b` とします。パーセプトロンは `w・x + b` を計算し、正なら `+1`、それ以外なら `-1` と答えます。`w・x` は、列ごとに重みと値を掛けて足した内積で、[ベクトルと行列の演算](../../math/vector-matrix-ops/)で説明しています。

学習の規則は 1 つだけです。正解を `t`（`+1` か `-1`）として、`t (w・x + b) <= 0` なら予測を誤ったとみなし、`w ← w + η t x`、`b ← b + η t` と直します。`η` が学習率です。正解が `+1` の行を誤ったら `x` を足し、`-1` の行を誤ったら `x` を引きます。正しく答えた行では何もしません。

次のコードは `η = 1` で、2 次元の点 16 個に対して、この規則を誤りが無くなるまで繰り返します。切片は、`x` の末尾に 1 を足した 3 列目の重みとして一緒に扱います。

```python
def train_trace(X2, t, max_epochs=100):
    Xa = np.c_[X2, np.ones(len(X2))]       # 3 列目は切片の分の 1
    w = np.zeros(3)
    trace = []
    for epoch in range(1, max_epochs + 1):
        mistakes = 0
        for i in range(len(Xa)):
            if t[i] * (Xa[i] @ w) <= 0:     # 予測の符号が正解と違う（0 も誤りとする）
                trace.append((epoch, i, w.copy()))
                w = w + t[i] * Xa[i]        # 正解が +1 なら足し、-1 なら引く
                mistakes += 1
        if mistakes == 0:
            return w, trace, epoch
```


{{< figure src="pc_updates.webp" alt="2 次元の 16 点に引いた線が、更新のたびに動く動画。青い丸が正解 +1、赤い四角が正解 -1 で、線の青い側が +1、赤い側が -1 と予測する領域。最初は w = 0 で線が無く、誤った点に丸が付くたびに、その点を正しい側に入れる向きへ線が回る。1 エポック目に 6 回、2 エポック目に 2 回、3 エポック目に 1 回更新し、4 エポック目で誤り 0 になって止まる" caption="パーセプトロンの更新（1 回の更新を 1 秒ずつ表示）" align="center" >}}

学習データを 1 周することを 1 エポックと呼びます。1 エポック目に 6 回、2 エポック目に 2 回、3 エポック目に 1 回更新し、4 エポック目は 1 点も誤らずに止まりました。正解が `+1` の点を誤って `x` を足すと、その点の `w・x` は `x・x` だけ増えるので、その点は正しい側へ近づきます。ただし、1 回で正しい側へ移るとは限らず、他の点を反対側へ押し出すこともあります。

step 関数は、正なら 1、それ以外は 0 か -1 を返す関数で、パーセプトロンの出力は `w・x + b` を step 関数に通したものです。step 関数を sigmoid や ReLU のような、傾きを計算できる関数に替えて層を重ねたものが多層パーセプトロンで、関数の違いは[活性化関数](../activation-functions/)で、層を重ねた時の学習は[誤差逆伝播法](../backpropagation/)で説明しています。

### 学習率で予測が変わらない理由

上記の規則では、`w` と `b` は 0 から始まり、更新のたびに `η t x` と `η t` が足されます。何回更新しても、`w` は「誤った行の `t x` を足した合計」に `η` を掛けたものです。予測は `w・x + b` の符号だけで決まり、正の数 `η` を掛けても符号は変わりません。

そのため `η` が違っても、同じ行を同じ順に誤ります。冒頭の図は、次のコードで描きました。

```python
X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0, stratify=y)
scaler = StandardScaler().fit(X_train)
X_train, X_test = scaler.transform(X_train), scaler.transform(X_test)

etas = [1e-6, 1e-4, 1e-2, 1.0, 1e2, 1e4, 1e6]
preds, norms = [], []
for eta in etas:
    clf = Perceptron(eta0=eta, tol=None, max_iter=50, random_state=0).fit(X_train, y_train)
    pred = clf.predict(X_test)
    preds.append(pred)
    norms.append(np.linalg.norm(clf.coef_))
    print(f"eta0={eta:<8g} 重みの長さ {norms[-1]:.3e}  テストの正解率 {clf.score(X_test, y_test):.3f}"
          f"  eta0=1e-6 と予測が違う行 {(pred != preds[0]).sum()}")
```

列の値は、各列を平均 0・分散 1 にそろえる[標準化](../standardization/)をしてから渡しています。列の大きさがそろっていないと、`w・x` も更新で足す `x` も、値の大きい列に引っ張られるためです。`tol=None` は、後の節で説明する早めに止める仕組みを切る指定で、どの `eta0` でもちょうど 50 エポック回します。

この性質は、重みが 0 から始まり、`η` が全体に掛かる倍率であることに頼っています。`fit` の `coef_init` で初期の重みに乱数を入れると、`eta0` が 0.01 の時と 1 の時で、テストの予測が 5 行変わりました。[正則化](../regularization/)で重みを縮める時や、`learning_rate="adaptive"` のように学習率を途中で変える時も、同じ議論は成り立ちません。

<br>

<details>
<summary>ロジスティック回帰では学習率が効く理由</summary>

[ロジスティック回帰](../logistic-regression/)を同じように 1 行ずつ学習させると、誤ったかどうかに関係なく全ての行で重みを直します。直す量は `w・x + b` を sigmoid に通した確率で決まり、確率は `w` の大きさで変わります。学習率を変えると行ごとに直す量の比が変わるので、学習の結果も変わります。

</details>

### 止まるまでの更新の回数

前の節で使った 16 点は、1 本の直線で 2 つの分類を完全に分けられました。このようなデータを線形分離可能と呼びます。列が 3 つ以上なら、直線の代わりに平面や超平面で分けます。

線形分離可能なデータでは、パーセプトロンは必ず有限回の更新で誤り 0 になって止まります。1962 年に [Novikoff 氏が示した](https://cs.uwaterloo.ca/~y328yu/classics/novikoff.pdf)上限では、更新の回数は `(R / γ)²` 以下です。`R` は原点から一番遠い点までの距離です。

`γ` は次のように決めます。全ての点を正しく分ける線のうち、一番近い点までの距離が最も大きい線を選び、その距離をマージンと呼び、`γ` で表します。式では、`R` も `γ` も切片のために 1 を足した `x` で測ります。下の図は、形を見るために 2 次元のまま測ったものです。

{{< figure src="pc_gamma.webp" alt="前の節の 16 点に、マージンが最大になる緑の線と、その両側に γ の幅の点線を引いた図。線に一番近い赤い四角から線までの矢印が γ = 0.17、原点から一番遠い青い丸までの矢印が R = 1.38" caption="16 点で見た R と γ（2 次元のまま測った図）" align="center" >}}

上限は行の数にも列の数にも依らず、点が線に近いほど大きくなります。

2 次元の 200 点で、正解の線から一定の幅に入る点を捨ててマージンを作り、その幅を 0.2 から 0.002 まで狭めました。幅ごとに点の選び方と学習の順番を変えて 20 回、誤り 0 になるまでの更新を数えます。`γ` は点を作った線 `w_star` で測るので最大のマージン以下になり、上限は本来より大きめに出ます。

```python
def count_updates(Xa, t, rng=None, max_epochs=100000):
    w = np.zeros(Xa.shape[1])
    n = 0
    for epoch in range(1, max_epochs + 1):
        mistakes = 0
        idx = rng.permutation(len(Xa)) if rng is not None else range(len(Xa))
        for i in idx:
            if t[i] * (Xa[i] @ w) <= 0:
                w = w + t[i] * Xa[i]
                n += 1
                mistakes += 1
        if mistakes == 0:
            return n, epoch


u = np.array([np.cos(0.6), np.sin(0.6)])
for gap in [0.2, 0.1, 0.05, 0.02, 0.01, 0.005, 0.002]:
    ups, bs = [], []
    for s in range(20):
        r = np.random.default_rng(s)
        P = r.uniform(-1, 1, (4000, 2))
        d = P @ u - 0.2
        keep = np.abs(d) > gap                      # 線から gap 以内の点を捨ててマージンを作る
        Xa = np.c_[P[keep][:200], np.ones(200)]
        t = np.sign(d[keep][:200])
        w_star = np.r_[u, -0.2]
        gamma = (t * (Xa @ w_star)).min() / np.linalg.norm(w_star)
        R = np.linalg.norm(Xa, axis=1).max()
        ups.append(count_updates(Xa, t, r)[0])
        bs.append((R / gamma) ** 2)
```

{{< figure src="pc_margin.webp" alt="両対数のグラフ。横軸は線から点を捨てた幅で、右へ行くほど 0.2 から 0.002 へ狭くなる。灰色の破線の上限 (R/γ)² は 71 から 103,339 まで直線的に増える。青の実際に更新した回数の中央値は 9 から 118、赤の 20 回の最大は 15 から 331 で、上限より 1 桁弱から 3 桁弱だけ下にある" caption="マージンを狭めた時の、上限（点を作った線で測る）と実際に更新した回数" align="center" >}}

幅を 100 分の 1 にすると、上限は 71 から 103,339 まで 1,400 倍ほどに増えました。実際に更新した回数は、[中央値](../../math/median/)で 9 から 118、20 回の最大でも 331 です。上限は「これより多くはならない」という保証で、この実験では実際の回数より 1 桁弱から 3 桁弱大きく、何回で止まるかの目安にはなりませんでした。マージンが狭いほど回数が増える傾向は、上限と同じです。

breast_cancer の学習データ 426 行も、線形分離可能でした。マージンを最大にする線を引く[線形 SVM](../svm/) に `C=1e8` を与えて学習させると、426 行を全て正しく分けます。`C` は誤りをどこまで許すかを決める引数で、大きいほど許しません。この線で測った `γ` は 0.0402、`R` は 20.12 で、上限は 250,695 回です。上記の `count_updates` を行の順番のまま回すと、1,808 回の更新、241 エポックで誤り 0 になりました。

### scikit-learn の Perceptron が止まる所

scikit-learn の `Perceptron` は、既定では `max_iter=1000` エポックまで回しますが、その前に止まる仕組みがあります。判定には損失を使います。損失は、誤った行では `-t (w・x + b)`、正しく答えた行では 0 で、これを 1 エポック分足して行の数で割ったものが損失の平均です。この平均が、それまでの最小より `tol=1e-3` 以上は下がらないエポックが `n_iter_no_change=5` 回続くと止まります。

`w` と `b` が `η` 倍になれば、損失も `η` 倍になります。`tol` は損失の大きさと直接比べるので、`eta0` が小さいほど、下がり方が `tol` に届かず早く止まります。止める仕組みを切らずに `eta0` を変えました。

```python
base = None
for eta in etas:
    clf = Perceptron(eta0=eta, random_state=0).fit(X_train, y_train)
    pred = clf.predict(X_test)
    base = pred if base is None else base
    print(f"eta0={eta:<8g} n_iter_={clf.n_iter_:2d}  学習データの正解率 {clf.score(X_train, y_train):.3f}"
          f"  テストの正解率 {clf.score(X_test, y_test):.3f}  eta0=1e-6 と予測が違う行 {(pred != base).sum()}")
```

`n_iter_` は実際に回したエポックの数です。`eta0` が 1e-4 以下では、最初のエポックを終えた後に 5 回続けて止める条件を満たし、最短の 6 エポックで止まりました。`eta0` が 1 以上では 8 エポックで止まり、6 エポックで止めた時とはテストの予測が 7 行違います。

既定の `eta0=1` で、止める仕組みを切り、エポックごとに損失の平均と学習データの誤りを数えました。損失の平均は、`verbose=1` を付けると出力の `Avg. loss` で読めます。

上の段では、損失の平均はエポック 3 の 0.139 が最小で、エポック 4〜8 の 5 回はどれもそれより下がりません。そのため既定の設定はエポック 8 で、学習データの誤りが 12 行残ったまま止まります。誤りが初めて 0 になったのはエポック 357 で、その後は誤る行が無いので更新もありません。breast_cancer は線形分離可能なので、更新を続ければ誤り 0 になるのに、既定の設定はその手前で止まります。止まった時に警告は出ません。

#### 誤り 0 まで回した線は、テストで当たるか

`random_state` は、エポックごとに学習データを並べ替える乱数の種です。種を 50 通り変えて、既定の設定、誤り 0 まで回す設定、重みを平均する設定の 3 つで、テストの正解率を比べました。

重みを平均する設定（平均化）は、最後の重みではなく、更新の途中で現れた重みを全て平均して予測に使うもので、Freund 氏と Schapire 氏が [1999 年の論文](https://doi.org/10.1023/A:1007662407062)で示した averaged perceptron と同じ考え方です。`Perceptron` には平均化の引数が無いので、[`SGDClassifier`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.SGDClassifier.html) で代用します。

`Perceptron` の文書には、`Perceptron()` は `SGDClassifier` に `loss="perceptron"`、`eta0=1`、`learning_rate="constant"`、`penalty=None` を指定したものと同じだと書かれているので、これに `average=True` を足しました。止め方は既定の `tol=1e-3` のままで、既定の `Perceptron` と同じです。

```python
for s in range(50):
    m = Perceptron(random_state=s).fit(X_train, y_train)
    results["既定（tol=1e-3）"].append(m.score(X_test, y_test))
    m = Perceptron(tol=None, max_iter=1000, random_state=s).fit(X_train, y_train)
    assert m.score(X_train, y_train) == 1.0
    results["誤り 0 まで（tol=None）"].append(m.score(X_test, y_test))
    m = SGDClassifier(loss="perceptron", learning_rate="constant", eta0=1, penalty=None,
                      average=True, random_state=s).fit(X_train, y_train)
    results["平均化（average=True）"].append(m.score(X_test, y_test))
```

```text
既定（tol=1e-3）           最小 0.916  中央値 0.951  最大 0.965
誤り 0 まで（tol=None）      最小 0.930  中央値 0.937  最大 0.944
平均化（average=True）      最小 0.944  中央値 0.958  最大 0.979
既定の n_iter_: 最小 6、最大 21
LogisticRegression（既定）0.958、SVC(kernel='linear')（既定の C=1）0.965
```

{{< figure src="pc_seeds.webp" alt="3 段の点の図。横軸はテストの正解率で 0.92 から 0.98。下の段の既定（tol=1e-3）は 0.916 から 0.965 に広がり中央値 0.951。中の段の誤り 0 まで（tol=None）は 0.930 から 0.944 に固まり中央値 0.937。上の段の平均化（average=True）は 0.944 から 0.979 で中央値 0.958。灰色の破線は LogisticRegression の 0.958" caption="random_state を 50 通り変えて測ったテストの正解率" align="center" >}}

学習データを全問正解するまで回すと、テストの正解率は 50 通りとも 0.944 以下で、中央値は既定より低い 0.937 でした。テスト 143 行のうち 2 行ほどの差で、1 回の分割で得た結果です。最後の重みは、最後に誤った数行を足したり引いたりした結果なので、分類の境目に近い数行に合わせて線が動き、その位置で止まったためと考えられます。言えるのは、この分割では誤り 0 まで回してもテストの正解率が良くならなかった、ということまでです。[過学習](../overfitting/)と同じことが起きているかは、分割を変えて検証する必要があります。

平均化の中央値は 0.958 で、正則化を掛けた既定の `LogisticRegression` と同じ値でした。`C=1` を既定とする線形 SVC は 0.965 です。

### ロジスティック回帰・SVM との違い

前の節では、誤り 0 まで回した線で測ると、テストの正解率が既定より中央値で 2 行ほど低くなりました。その一因として考えられるのが、パーセプトロンが「正しい側に入った点」をそれ以上気にしないことです。

2 次元に赤 40 点・青 40 点の 2 つの集まりを置き、`X6` と `y6` にしました。この 80 点に、パーセプトロンを乱数の種 30 通りで、線形 SVM と `LogisticRegression` を正則化をほぼ外した `C=1e6` で学習させ、引いた線を重ねました。

```python
r = np.random.default_rng(3)
X6 = np.r_[r.normal([0.0, 0.2], 0.45, (40, 2)), r.normal([2.0, 1.6], 0.45, (40, 2))]
y6 = np.r_[np.zeros(40), np.ones(40)]  # 0 が赤、1 が青
for s in range(30):
    m = Perceptron(tol=None, max_iter=1000, random_state=s).fit(X6, y6)
    assert m.score(X6, y6) == 1.0
    lines.append((m.coef_[0] / np.linalg.norm(m.coef_[0]), m.intercept_[0] / np.linalg.norm(m.coef_[0])))
svm6 = SVC(kernel="linear", C=1e6).fit(X6, y6)
lr6 = LogisticRegression(C=1e6, max_iter=10000).fit(X6, y6)
```


パーセプトロンの 30 本は、どれも 80 点を全て正しく分けますが、向きは 49 度の幅に広がりました。線から一番近い点までの距離は、中央値で 0.143、一番近い線では 0.019 です。線形 SVM はこの距離を最大にする線を引くので 0.420 で、`LogisticRegression` もほぼ同じ所に線を引きます。違いは、正しく分けた点を損失がどう扱うかにあります。

| | パーセプトロン | ロジスティック回帰 | 線形 SVM |
|---|---|---|---|
| 正しい側にある点の損失 | 0 | 線から離れるほど 0 に近づく | 線から一定の距離を超えると 0 |
| 誤り 0 になった後 | 更新が止まる | 点から離す向きに動き続ける | マージンが最大の線に収まる |
| 乱数の種で線が変わるか | 変わる | 変わらない | 変わらない |
| 確率を出せるか | 出せない | 出せる | 出せない |

ロジスティック回帰の損失は、[損失関数](../loss-functions/)で説明している交差エントロピーで、正しく分けた点でも 0 にはならず、線から離すほど小さくなります。正しく分けた点からも[勾配](../../math/partial-derivative-gradient/)を受け取り続けるということです。そのため線は 2 つの点の集まりの真ん中へ動きます。パーセプトロンは誤り 0 になった時点で更新が止まるので、どの線で止まるかは、点を見た順番で決まります。

### 線で分けられない分岐

線形分離可能でないデータでは、全ての点を正しく分ける線が無いので `γ` を取れず、前の上限は使えません。代表は排他的論理和（XOR）で、2 つの入力のどちらか一方だけが 1 の時に 1 を返します。`(0, 0)` と `(1, 1)` が 0、`(0, 1)` と `(1, 0)` が 1 なので、正方形で対角に並ぶ 2 組を 1 本の直線で分けることはできません。

この限界は、Minsky 氏と Papert 氏が 1969 年の本 [Perceptrons](https://doi.org/10.7551/mitpress/11301.001.0001)（リンク先は 2017 年の再刊）で詳しく論じました。

入力と出力に挟まれた層を隠れ層と呼び、隠れ層を持つものを多層パーセプトロンと呼びます。XOR の 4 点で、`Perceptron` と、4 ユニットの隠れ層を 1 つ持つ [`MLPClassifier`](https://scikit-learn.org/stable/modules/generated/sklearn.neural_network.MLPClassifier.html) を比べました。

```python
X_xor = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])
y_xor = np.array([0, 1, 1, 0])
p = Perceptron(tol=None, max_iter=1000, random_state=0).fit(X_xor, y_xor)
print("Perceptron の予測:", p.predict(X_xor), " 正解:", y_xor)
mlp = MLPClassifier(hidden_layer_sizes=(4,), activation="tanh", solver="lbfgs", random_state=0).fit(X_xor, y_xor)
print("MLPClassifier（隠れ層 4 ユニット）の予測:", mlp.predict(X_xor))
```

```text
Perceptron の予測: [0 0 0 0]  正解: [0 1 1 0]
MLPClassifier（隠れ層 4 ユニット）の予測: [0 1 1 0]
```

{{< figure src="pc_xor.webp" alt="左右 2 枚の図に、XOR の 4 点を置いたもの。(0, 1) と (1, 0) が青い丸の正解 1、(0, 0) と (1, 1) が赤い四角の正解 0。左の Perceptron は全面が赤で、4 点中 2 点だけ当たる。右の MLPClassifier は、左上から右下へ斜めに走る青い帯で 2 つの青い丸を囲み、4 点とも当たる" caption="XOR の 4 点で、Perceptron と隠れ層のある MLP が予測した領域" align="center" >}}

`Perceptron` は 1000 エポック回しても 4 点のうち 2 点しか当てられず、最後の重みでは全てを 0 と答えました。隠れ層のある `MLPClassifier` は、曲がった帯で 2 つの青い丸を囲んで、4 点とも当てます。

誤りのたびに足す規則で、`w = 0` から行の順番のまま XOR を学習させると、毎エポック 4 点全てを誤り、エポックの終わりに `w` は 0 へ戻ります。1 点を直すたびに別の点を壊し、同じ重みに戻るので、何エポック回しても止まりません。

<br>

#### 隠れ層が入力を移す

隠れ層が何をしているかは、重みを手で決めると見えます。次のコードは、step 関数を使うパーセプトロンを 3 個組み合わせます。隠れ層の `h1` はどちらかの入力が 1 なら 1 を返す OR、`h2` は両方が 1 の時だけ 0 を返す NAND（AND の否定）で、出力層は `h1` と `h2` の AND を取ります。

```python
step = lambda z: (z > 0).astype(int)
h1 = step(X_xor @ np.array([1, 1]) - 0.5)     # OR
h2 = step(X_xor @ np.array([-1, -1]) + 1.5)   # NAND（AND の否定）
print("h1 =", h1, "h2 =", h2, "出力 =", step(h1 + h2 - 1.5))  # AND
```

```text
h1 = [0 1 1 1] h2 = [1 1 1 0] 出力 = [0 1 1 0]
```

{{< figure src="pc_hidden.webp" alt="3 つの図を横に並べたもの。左は入力 x1・x2 から隠れ層の h1（OR、重み 1 と 1、切片 -0.5）と h2（NAND、重み -1 と -1、切片 1.5）へ、そこから出力（AND、重み 1 と 1、切片 -1.5）へ矢印が伸びる構造図。中は入力の 4 点で、青い丸の (0, 1) と (1, 0)、赤い四角の (0, 0) と (1, 1) に、h1 の線 x1+x2=0.5 と h2 の線 x1+x2=1.5 の 2 本を引いたもの。右は隠れ層が移した先で、入力 (0, 0) は (0, 1)、入力 (1, 1) は (1, 0) に移り、入力 (0, 1) と (1, 0) はどちらも (1, 1) に重なる。緑の出力の線 h1+h2=1.5 が、(1, 1) の青い丸と 2 つの赤い四角を分ける" caption="手で重みを決めた 3 個のパーセプトロンが、XOR の 4 点を移す先" align="center" >}}

入力の 4 点は、隠れ層で `(h1, h2)` という新しい 2 列に移ります。`(0, 0)` は `(0, 1)` へ、`(1, 1)` は `(1, 0)` へ移り、XOR が 1 の `(0, 1)` と `(1, 0)` はどちらも `(1, 1)` に重なります。移した先では、出力層の 1 本の線 `h1 + h2 = 1.5` で 2 つの分類を分けられます。隠れ層は、1 本の線で分けられない入力から、分けられる列を作っています。

`MLPClassifier` は、この重みを手で決める代わりに学習します。step 関数は傾きがほぼどこでも 0 で、重みをどちらへ動かせばよいかが分からないので、tanh のような傾きのある活性化関数に替えています。

隠れ層を 1 つ持つネットワークは、ユニットを増やせば、決めた範囲の連続関数をいくらでも近く表せます。sigmoid 型の活性化関数について [Cybenko 氏が 1989 年に示した](https://doi.org/10.1007/BF02551274)もので、普遍近似定理と呼ばれます。ただし、定理が保証するのはそういう重みがあることだけで、ユニットが何個要るかや、学習でその重みに届くかは保証しません。

パーセプトロンは、CPU の分岐予測にも使われています。CPU は条件分岐の結果が出る前に、どちらへ進むかを予測して先の命令を読み込みます。外れると読み込んだ命令を捨てるので、予測の精度は速度に直結します。予測の元にするのは、直前の分岐が成立したか（taken）しなかったかを並べた履歴です。

<br>

#### 分岐予測とパーセプトロン

Jiménez 氏と Lin 氏は [2001 年の論文](https://doi.org/10.1109/HPCA.2001.903263)で、分岐のアドレスでパーセプトロンを 1 つ選び、直近の履歴を `+1`（成立）と `-1`（不成立）の入力にする予測器を提案しました。それまでの代表的な予測器は、履歴と分岐のアドレスを組み合わせた番号で表を引き、引いた欄にある 2 ビットのカウンタで予測します。

2 ビットのカウンタは 0〜3 の数で、成立なら 1 増やし、不成立なら 1 減らし、2 以上なら成立と予測します。

表は、履歴の並びを全て区別するなら 1 通りごとに 1 欄が要るので、履歴を 1 個延ばすたびに大きさが 2 倍になります。パーセプトロンは、履歴 1 個につき重みが 1 個増えるだけです。実際の予測器は、どちらも 1 つの表やパーセプトロンを多くの分岐で共有するので、次の図で比べるのは履歴を延ばした時の増え方です。

{{< figure src="pc_storage.webp" alt="片対数のグラフ。横軸は予測に使う履歴の長さ h で 1 から 32、縦軸はカウンタ・重みの数。灰色の表は 2 ビットのカウンタが 2^h 個で、h=8 で 256 個、h=13 で 8,192 個、h=16 で 65,536 個と直線的に増え、h=32 で 40 億を超える。青のパーセプトロンは重みが h + 1 個で、h=16 でも 17 個" caption="履歴を延ばした時に増える、表のカウンタとパーセプトロンの重み" align="center" >}}

履歴の長さ `h` が 16 なら、全ての並びを区別する表は 65,536 個のカウンタが要り、パーセプトロンは 1 つあたり 17 個の重みで済みます。遠い過去の分岐まで見たい時に、パーセプトロンが有利になります。

この方式は製品にも入りました。[Samsung が Exynos の CPU 設計を振り返った論文](https://people.engr.tamu.edu/djimenez/pdfs/exynos_isca2020.pdf)（ISCA 2020）によれば、Exynos M1 以降の世代は、パーセプトロンを改良した Scaled Hashed Perceptron を使っています。

<br>

ここで、XOR の節で見た限界が CPU でも問題になります。

Jiménez 氏と Lin 氏の論文は、パーセプトロンが完全に学べるのは線で分けられる関数だけだと述べ、線で分けられない分岐の例として「3 個前と 5 個前の分岐で排他的論理和を取り、真なら成立する分岐」を挙げています。

予測器に使える記憶を 512K バイトにそろえた測定（論文の Figure 8）では、線で分けられない分岐の方が多いベンチマークのうち 1 つを除いて、表を引く予測器の方が外す割合が低くなりました。

そこで、論文の例と同じく 3 個前と 5 個前の排他的論理和で決まる分岐 B と、比べるために 13 個前と同じ結果になる分岐 B を用意しました。B の前に 5 個の分岐がランダムに入るプログラムを模擬し、3 つの予測器を比べます。

| 予測器 | 入力にする履歴 | 保持する数 |
|---|---|---|
| 表 | 直近 8 個を番号にして 1 欄を引く | 2 ビットのカウンタ 256 個 |
| パーセプトロン | 直近 16 個 | 切片を含む重み 17 個 |
| パーセプトロン＋積の列 | 上記と「3 個前 × 5 個前」の列 | 重み 18 個 |

「N 個前」は直前の分岐を 1 個前として数え、B が過去に出した結果も履歴に入ります。

2 つのパーセプトロンは論文と同じく、外した時に加えて、当たっても `w・x + b` の絶対値が閾値以下の時に重みを更新します。当たった点でも線から近ければ直すので、γ の説明で出てきたマージンと同じ考え方です。

次のコードは、perceptron_gen.py の関数 `simulate(kind, seed)` の中身で、`kind` に渡した決め方で B を 3 万回予測します。

```python
H, K, THETA, N_ITER, N_OTHER = 16, 8, 30, 30000, 5
rng = np.random.default_rng(seed)
hist = list(rng.choice([-1, 1], size=H))        # hist[0] が直前の分岐。+1 が成立、-1 が不成立
w = np.zeros(H + 1)                              # 切片の分 + 履歴 16 個の重み
wx = np.zeros(H + 2)                             # 上記に「3 個前 × 5 個前」の積を 1 列足したもの
table = np.full(2 ** K, 1)                       # 直近 8 個の履歴で引く 2 ビットのカウンタ 256 個
miss = {"表（直近 8 個の履歴、256 個のカウンタ）": [], "パーセプトロン（16 個の履歴、17 個の重み）": [],
        "パーセプトロン＋積の列（18 個の重み）": []}  # 予測器ごとに、外したかを溜める
names = list(miss)
for _ in range(N_ITER):
    for _ in range(N_OTHER):                     # 予測しない分岐が 5 個、ランダムに成立する
        hist.insert(0, rng.choice([-1, 1]))
        hist.pop()
    h = np.array(hist)
    if kind == "13 個前と同じ":
        t = h[12]
    else:                                        # 3 個前と 5 個前の排他的論理和
        t = -h[2] * h[4]
    idx = int("".join("1" if b > 0 else "0" for b in h[:K]), 2)
    p = 1 if table[idx] >= 2 else -1
    miss[names[0]].append(p != t)
    table[idx] = min(3, table[idx] + 1) if t > 0 else max(0, table[idx] - 1)
    for key, vec, x in [(names[1], w, np.r_[1, h]), (names[2], wx, np.r_[1, h, h[2] * h[4]])]:
        out = vec @ x
        p = 1 if out >= 0 else -1
        miss[key].append(p != t)
        if p != t or abs(out) <= THETA:          # 誤った時と、出力が閾値より小さい時に更新
            vec[:] = np.clip(vec + t * x, -128, 127)   # 重みは 8 ビットの範囲に収める
    hist.insert(0, t)
    hist.pop()
```

```text
13 個前と同じ         パーセプトロン＋積の列（18 個の重み）       予測を外した割合 0.000
3 個前と 5 個前の排他的論理和 表（直近 8 個の履歴、256 個のカウンタ）    予測を外した割合 0.000
3 個前と 5 個前の排他的論理和 パーセプトロン（16 個の履歴、17 個の重み）   予測を外した割合 0.499
3 個前と 5 個前の排他的論理和 パーセプトロン＋積の列（18 個の重み）       予測を外した割合 0.000
```

B が 13 個前の分岐と同じ結果になる時、表は 8 個前までしか見ないので半分外し、パーセプトロンは 1 回も外しません。学習した重みは、13 個前の重みが 46 で、他は -2〜2 でした。表で 13 個前まで見るには、カウンタが 2 の 13 乗の 8,192 個要ります。

B が 3 個前と 5 個前の排他的論理和で決まる時は逆で、表は全て当て、パーセプトロンは半分外します。排他的論理和のように線で分けられない組み合わせは、1 個ずつの履歴に重みを掛けて足すだけでは表せないからです。「3 個前 × 5 個前」の列を 1 つ足すと、その列の符号だけで答えが決まり、外す割合は 0 になりました。

この列は、XOR の節で手で決めた `h1`・`h2` と同じく入力から作った列で、多層パーセプトロンは同じような列を隠れ層で学習します。

隠れ層の重みは、1986 年の Rumelhart 氏・Hinton 氏・Williams 氏の[論文](https://doi.org/10.1038/323533a0)で広まった[誤差逆伝播法](../backpropagation/)で学習します。LLM の中で多層パーセプトロンが担う部分は、[Mixture of Experts](/notes/generative-ai/mixture-of-experts/) で説明しています。

---

### Perceptron を使う前に見ること

scikit-learn の `Perceptron` をハイパーパラメータの探索にかけるなら、`penalty=None` のままの間は `eta0` を候補から外せます。この時 `eta0` が変えるのは止まるエポックだけなので、動かすのは止め方の `tol` と `max_iter` で、学習の後は `n_iter_` で何エポック回ったかを見ます。

正則化の `penalty` と `alpha` を探索するなら、`eta0` も予測に効くので一緒に動かします。

<br>

学習データの正解率が 1 にならない時は、線形分離可能かを先に調べます。誤りをほぼ許さない線形 SVM で学習データを全て正しく分けられれば分離可能です。breast_cancer では次のようになりました。

```python
svm_hard = SVC(kernel="linear", C=1e8).fit(X_train, y_train)
print(f"breast_cancer: 学習データの正解率（線形 SVM、C=1e8）{svm_hard.score(X_train, y_train):.3f}")
```

```text
breast_cancer: 学習データの正解率（線形 SVM、C=1e8）1.000
```

分けられなければ分離可能でない可能性が高く、パーセプトロンを何エポック回しても誤りは 0 になりません。

止まった線をそのまま使うかも考えます。誤り 0 まで回した線は境目の点のすれすれを通ることがあり、breast_cancer のこの分割では、テストの正解率が既定より中央値で 2 行ほど低く、平均化は既定より高くなりました。どちらも 1 回だけ分けた時に数行違っただけなので、自分のデータでは平均化（`average=True`）と既定の線を交差検証で比べます。

乱数の種で変わらない線が欲しいならロジスティック回帰か線形 SVM を使います。確率が要るならロジスティック回帰です。正解率の差が乱数の種で動く範囲より大きいかは、[交差検証](../cross-validation/)で見ます。

データが後から届く時は、`partial_fit` で届いた分だけを足して学習させられます。3 つ以上の分類では、`Perceptron` は分類ごとに「その分類か、それ以外か」を分けるパーセプトロンを 1 つずつ学習させ、出力が一番大きい分類を答えます。この方式を one-vs-rest と呼びます。

<br>

正解率がどの設定でも上がらないなら、線で分けられない組み合わせが残っている可能性があります。分岐予測の実験のように、結果に関わる列どうしの積を足すか、隠れ層のあるモデルに替えます。
