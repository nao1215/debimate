ベイズの定理（Bayes' theorem）は、条件と結果を入れ替えた確率を求める式です。「石灰化なら判定が陽性になる確率」から「判定が陽性なら石灰化である確率」を出す時に使い、陽性がどれだけ珍しいかという割合が、2 つの確率をつなぎます。

[OpenML](https://www.openml.org/d/310) で公開されている mammography は、乳房の X 線写真から見つけた候補 11183 件について、本物の石灰化かどうかを 6 列の特徴から当てるデータです。元は Woods らが 1993 年に石灰化の検出手法を比べた[研究](https://doi.org/10.1142/S0218001493000698)のデータです。石灰化は 260 件、全体の 2.3% しかありません。以下では、石灰化を陽性、それ以外を陰性と呼びます。

陽性が少ないので、[scikit-learn](https://scikit-learn.org/stable/) の [`LogisticRegression`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html) に、少ない側を重く扱う `class_weight="balanced"` を渡して半分で学習し、残りの 5592 件で予測確率を出しました。

```python
balanced = LogisticRegression(max_iter=1000, class_weight="balanced").fit(X_tr, y_tr)
p_bal = balanced.predict_proba(X_te)[:, 1]   # 石灰化である確率
sel = (p_bal >= 0.8) & (p_bal < 0.9)
print(sel.sum(), y_te[sel].sum())            # 0.8〜0.9 を付けた件数と、そのうちの石灰化
```

確率 0.8 以上 0.9 未満を付けた画像は 74 件ありました。このうち本当に石灰化だった画像は、何件だと思いますか。

<br>

答えは 11 件、15% でした。確率どおりなら 60 件を超えるはずです。予測確率を 0.1 刻みの区間に分け、区間ごとに実際に石灰化だった割合を並べたのが次の図です。

{{< figure src="bayes_cover.webp" alt="横軸は予測確率の区間ごとの平均、縦軸はその区間で実際に陽性だった割合。点線の対角線が確率どおりの線。青の重み無しと、緑の balanced をベイズの定理で補正した線は対角線の近くを通る。赤の class_weight=balanced は全ての区間で対角線より大きく下にあり、0.85 付近の点に「0.8〜0.9 の 74 件のうち陽性は 11 件」の注記がある。0.97 付近でも 0.57 にとどまる" caption="mammography のテスト 5592 件で、予測確率と実際に陽性だった割合" align="center" >}}

赤い `class_weight="balanced"` の線は、全ての区間で確率どおりの点線より下にあり、0.5〜0.6 を付けた 182 件では石灰化は 4% でした。重みを付けずに学習した青い線は、点線に沿います。

`balanced` は陽性と陰性で重みの合計が揃うように重みを付けるので、陽性が半分を占めるデータで学習したのに近い確率を返します。緑の線は、学習データで陽性が占める 2.3% を前提にした確率へ、ベイズの定理で戻したものです。どの確率を返す時も、scikit-learn はエラーや警告を出しません。

<br>

不均衡なデータの解説では、`class_weight="balanced"` や、陽性と同じ数だけ陰性を残して学習するアンダーサンプリングがよく勧められます。確率の順に上位から人が見るだけなら困りませんが、予測確率に金額を掛けて損失を見積もる時や、0.8 以上を自動で止める時は、上記の図のずれがそのまま判断のずれになります。

<br>

本記事では、ML の説明に出てくる条件付き確率の式を自分で計算して確認したい人と、scikit-learn の `predict_proba` を確率として使う人に向けて、次の疑問に答えます。

- ベイズの定理は、どの確率をどの確率に変える式か。
- 陽性の割合が変わると、Precision はどれだけ動くか。
- `class_weight="balanced"` の確率は、学習し直さずに戻せるか。
- 確率を戻す方法は、補正と校正でどう違うか。
- 本番で陽性が占める割合は、少ない正解からどう見積もるか。
- ナイーブベイズの確率が 0 か 1 に張り付くのはなぜか。

### 条件と結果を入れ替える式

本文のコードは抜粋です。`plain` は重みを付けずに学習した同じロジスティック回帰、`p_plain` はその予測確率、`prior` は学習データで陽性が占める割合、`rng` は NumPy の乱数生成器を指します。データを読み込んで学習と評価に半分ずつ分ける所まで含めた完全なコードは [bayes-theorem_gen.py](https://github.com/nao1215/debimate/blob/main/projects/ml/scripts/notes/bayes-theorem_gen.py) にあり、scikit-learn 1.9.1 と [NumPy](https://numpy.org/) 2.5.4 で動かしました。

<br>

`P(A | B)` は、B が起きたと分かっている時に A が起きる確率で、条件付き確率と呼びます。件数の表から条件付き確率を読む方法は、[同時分布・周辺分布・条件付き分布](../joint-marginal-conditional/)で説明しています。冒頭で学習した `balanced` のモデルで、`predict` と同じ閾値 0.5 を使って判定を数えます。

石灰化を判定陽性にした件数を TP、判定陰性にした件数を FN、石灰化でない画像を判定陽性にした件数を FP、判定陰性にした件数を TN と書きます。この 4 つを並べた表が[混同行列](../../ml/confusion-matrix/)です。

```python
pred = (p_bal >= 0.5).astype(int)                       # predict と同じ閾値 0.5
tp = int(((pred == 1) & (y_te == 1)).sum()); fn = int(((pred == 0) & (y_te == 1)).sum())
fp = int(((pred == 1) & (y_te == 0)).sum()); tn = int(((pred == 0) & (y_te == 0)).sum())
recall = tp / (tp + fn); fpr = fp / (fp + tn); prev = (tp + fn) / len(y_te)
bayes = recall * prev / (recall * prev + fpr * (1 - prev))
print(f"TP {tp}  FN {fn}  FP {fp}  TN {tn}")
print(f"ベイズの定理で求めた P(石灰化 | 判定陽性) = {bayes:.3f}、数えた値 {tp}/{tp + fp} = {tp / (tp + fp):.3f}")
```

```text
TP 108  FN 22  FP 514  TN 4948
ベイズの定理で求めた P(石灰化 | 判定陽性) = 0.174、数えた値 108/622 = 0.174
```

{{< figure src="bayes_counts.webp" alt="左は横幅を件数の比にした面積の図。石灰化でない 5462 件の広い灰色の帯の下に、判定陽性の 514 件の青い帯がある。右端の幅 2.3% の細い帯が石灰化の 130 件で、うち判定陽性の 108 件が赤い。右は横棒 2 本で、判定陽性の画像 622 件のうち赤い 108 件は 17.4%、石灰化の画像 130 件のうち赤い 108 件は 83.1%" caption="同じ 108 件を判定陽性の 622 件で割るか、石灰化の 130 件で割るか" align="center" >}}

石灰化の 130 件のうち、判定が陽性になったのは 108 件で、`P(判定陽性 | 石灰化)` は 83.1% です。逆向きの `P(石灰化 | 判定陽性)` は、判定が陽性の 622 件のうちの 108 件で、17.4% しかありません。分子はどちらも同じ 108 件で、割る件数だけが違います。

判定陽性の 622 件の大半は、石灰化でない 5462 件から来た 514 件です。石灰化でない画像が判定陽性になる割合を偽陽性率（false positive rate, FPR）と呼び、コードの `fpr` がこれです。偽陽性率は 514 ÷ 5462 で 9.4% と小さいのですが、元の件数が 42 倍あるので、件数では石灰化を上回ります。

<br>

ベイズの定理は、この割り算を件数ではなく確率で書いたものです。

```text
P(石灰化 | 判定陽性) = P(判定陽性 | 石灰化) × P(石灰化) / P(判定陽性)

P(判定陽性) = P(判定陽性 | 石灰化) × P(石灰化) + P(判定陽性 | 石灰化でない) × P(石灰化でない)
            = 0.831 × 0.0232 + 0.094 × 0.9768
```

これを計算すると 0.174 になり、数えた値と一致します。この式は、石灰化で、かつ判定も陽性である確率 `P(石灰化, 判定陽性)` を 2 通りに書くと出てきます。

```text
P(石灰化, 判定陽性) = P(判定陽性 | 石灰化) × P(石灰化) = 108/130 × 130/5592 = 108/5592
                    = P(石灰化 | 判定陽性) × P(判定陽性) = 108/622 × 622/5592 = 108/5592
```

2 つの書き方は同じ値なので、両辺を `P(判定陽性)` で割れば上記の式になります。`P(判定陽性)` が 0 なら割れないので、0 より大きい時だけ使えます。値が連続の時は、確率の代わりに確率密度を使います。

<br>

判定を見る前の `P(石灰化)` を事前確率（prior probability）、判定を見た後の `P(石灰化 | 判定陽性)` を事後確率（posterior probability）と呼びます。`P(判定陽性 | 石灰化)` は、石灰化だと仮定した時にこの判定が出るもっともらしさで、尤度（likelihood）と呼びます。分母の `P(判定陽性)` は、石灰化の場合とそれ以外の場合を足し合わせたもので、周辺尤度（marginal likelihood）とも呼びます。

尤度は、仮説ごとに足しても 1 になるとは限りません。石灰化の 0.831 と石灰化でない 0.094 を足しても 0.925 です。事前確率との積を周辺尤度で割ることで、事後確率の合計が 1 に揃います。

<br>

仮説を `H`、観測したデータを `D` と書くと、ここまでの式は次の一般形になります。

```text
P(H | D) = P(D | H) × P(H) / P(D)        ただし P(D) > 0
P(D)     = Σ P(D | H) × P(H)              全ての仮説 H で足す
```

石灰化の例では、`H` が「石灰化」と「石灰化でない」の 2 つ、`D` が「判定陽性」でした。仮説が 3 つ以上ある時も、`P(D)` を全ての仮説で足すことだけが変わります。以降の節に出てくる `P(y | x)` や、割合 `θ` の事後分布も、この `H` と `D` を置き換えたものです。

ML の言葉では、`P(判定陽性 | 石灰化)` が Recall、`P(石灰化 | 判定陽性)` が Precision です。病気の検査では、それぞれ感度と陽性的中率と呼ばれます。

式の名前は、トーマス・ベイズが残した[論文](https://doi.org/10.1098/rstl.1763.0053)に由来します。ベイズの死後、Richard Price が 1763 年に王立協会の会報で発表しました。

### 陽性の割合と Precision

上記の式で右辺にある `P(判定陽性 | 石灰化)` と `P(判定陽性 | 石灰化でない)` は、石灰化とそれ以外のそれぞれの中で判定がどう出るかを表し、モデルと閾値で決まります。陽性が何割いるかは、`P(石灰化)` の 1 か所にしか入りません。テストの 5592 件から陽性か陰性の一部を選び直し、この割合だけを変えた時に Precision がどう動くかを数えました。

```python
pos_idx = np.where(y_te == 1)[0]; neg_idx = np.where(y_te == 0)[0]
for pi in [0.5, 0.2, 0.05, 0.01, 0.005]:
    vals = []
    for _ in range(200):
        n_pos = min(len(pos_idx), round(pi / (1 - pi) * len(neg_idx)))
        n_neg = round(n_pos * (1 - pi) / pi) if n_pos == len(pos_idx) else len(neg_idx)
        idx = np.r_[rng.choice(pos_idx, n_pos, replace=False), rng.choice(neg_idx, n_neg, replace=False)]
        hit = pred[idx] == 1
        vals.append(y_te[idx][hit].mean())             # 選び直した中での Precision
    print(f"陽性の割合 {pi:<5}: 数えた Precision {np.mean(vals):.3f}  "
          f"ベイズの定理 {recall * pi / (recall * pi + fpr * (1 - pi)):.3f}")
```

```text
陽性の割合 0.5  : 数えた Precision 0.897  ベイズの定理 0.898
陽性の割合 0.2  : 数えた Precision 0.689  ベイズの定理 0.688
陽性の割合 0.05 : 数えた Precision 0.317  ベイズの定理 0.317
陽性の割合 0.01 : 数えた Precision 0.082  ベイズの定理 0.082
陽性の割合 0.005: 数えた Precision 0.042  ベイズの定理 0.042
```

{{< figure src="bayes_prevalence.webp" alt="横軸は陽性の割合 P(石灰化) の対数目盛りで 0.2% から 50%、縦軸は Precision。黒い曲線はベイズの定理で求めた値で、0.2% の 0.02 付近から 50% の 0.9 まで S 字に上がる。赤い点はテストから選び直して数えた値で、0.5%・1%・5%・20%・50% の全てが曲線の上に乗る。青い菱形はテストそのままの 2.3% で 0.17" caption="モデルと閾値を固定し、陽性の割合だけを変えた時の Precision" align="center" >}}

同じモデル、同じ閾値でも、陽性が半分なら Precision は 0.90、1% なら 0.08 です。選び直して数えた値は、5 つの割合の全てでベイズの定理と 0.001 以内で一致しました。

テストのデータと本番で陽性の割合が違えば、テストで測った Precision は本番では当てになりません。陽性が 2.3% のこのデータでも、閾値 0.5 では判定陽性の 6 件に 5 件が外れです。ROC 曲線は Recall と偽陽性率だけで描くので、陽性の割合が変わっても変わりません。Precision を使う PR 曲線は変わります。この違いは [ROC-AUC / PR-AUC](../../ml/roc-pr-auc/) で説明しています。

### オッズで書くと、割合の違いは足し算になる

冒頭で `balanced` が返した確率を戻すには、ベイズの定理をオッズの形に書き直すと扱いやすくなります。オッズ（odds）は、確率 `p` を `p / (1 - p)` に直した値で、`p = 0.2` なら 0.25、つまり「陰性 4 に対して陽性 1」です。事後確率と事前確率をそれぞれオッズに直すと、`P(判定陽性)` の分母が消えて、次の形になります。

```text
事後オッズ = 事前オッズ × 尤度比
尤度比     = P(x | 石灰化) / P(x | 石灰化でない)
```

ここからは、閾値で決めた判定の代わりに、画像 1 件から取った 6 列の特徴 `x` そのものを条件にします。ロジスティック回帰が見ているのは判定ではなく特徴だからです。

両辺の log を取ると、事後の対数オッズは「事前の対数オッズ + 対数尤度比」の足し算になります。[ロジスティック回帰](../../ml/logistic-regression/)の出力は、切片と特徴の重み付きの和を対数オッズとして読んだものなので、陽性の割合に当たる部分は主に切片に入ります。log とオッズの関係は、[対数・指数と log-odds](../log-exp-logodds/) で説明しています。

`balanced` で学習したモデルは、陽性が半分のデータを見たのに近いので、事前の対数オッズが `log(0.5 / 0.5) = 0` のつもりで切片を決めます。学習データで陽性が占める割合を `π` とすると、事前の対数オッズは、本来なら `log(π / (1 - π))` で、`π = 0.0233` なら -3.74 です。重み無しのモデルと比べて、対数オッズが 3.74 ほど上にずれるはずです。

```python
logit = lambda p: np.log(p / (1 - p))
shift_theory = np.log((1 - prior) / prior)              # prior は学習データの陽性の割合 π
diff = logit(p_bal) - logit(p_plain)
print(f"切片の差（balanced - 重み無し）{(balanced.intercept_ - plain.intercept_)[0]:.2f}、"
      f"log((1 - π) / π) = {shift_theory:.2f}")
print(f"テスト 5592 件の対数オッズの差: 中央値 {np.median(diff):.2f}、"
      f"25% 点 {np.percentile(diff, 25):.2f}、75% 点 {np.percentile(diff, 75):.2f}")
```

```text
切片の差（balanced - 重み無し）4.08、log((1 - π) / π) = 3.74
テスト 5592 件の対数オッズの差: 中央値 4.34、25% 点 3.53、75% 点 4.34
```

[中央値](../median/)と 75% 点が同じ 4.34 なのは、テストの 1730 件が 6 列とも同じ値を持つ画像で、どちらのモデルでも同じ予測になるからです。差が 4.34 の画像は 1736 件あり、全体の 3 割を占めます。

{{< figure src="bayes_logodds.webp" alt="横軸は重み無しのモデルの対数オッズ、縦軸は class_weight=balanced のモデルの対数オッズで、テスト 5592 件を点で描いた散布図。青は石灰化でない画像、赤は石灰化。灰色の点線はずれ 0 の線。黒い実線はそれを log((1-π)/π)=3.74 だけ上にずらした線で、点の大半はこの実線の近くに帯になって並び、横軸 -10 から -4 のあたりでは青い点の一部が実線の左上に外れて並ぶ" caption="テストの 1 件ずつで、重み無しと balanced の対数オッズを比べた散布図" align="center" >}}

点の大半は、ずれ 0 の点線ではなく、3.74 だけ上にずらした実線に沿って並びます。ずれがぴったり 3.74 にならないのは、重みを付けると切片だけでなく特徴の重みも少し変わるからです。

実線の左上に外れて並ぶ青い点は、1 列目と 3 列目の値が大きく、6 列目の値が小さい画像です。重みを付けて学習すると 1 列目と 3 列目の重みが増え、6 列目の重みが減るので、その分がずれに加わります。差が 5 を超える画像は 230 件で、うち石灰化は 6 件です。それでも、`balanced` の確率のずれの大部分は、事前オッズを 1 と置いたことで説明できます。

#### 学習し直さずに確率を戻す

逆に、事前オッズを本来の値に直せば確率を戻せます。学習時に陽性が占めた割合 `prior_train` のオッズで割り、使いたい割合 `prior_new` のオッズを掛けて、確率に戻します。

```python
def correct(p, prior_train, prior_new):
    """学習時の陽性の割合 prior_train で出た確率 p を、割合 prior_new の確率に直す。"""
    odds = p / (1 - p) * (prior_new / (1 - prior_new)) / (prior_train / (1 - prior_train))
    return odds / (1 + odds)

p_fix = correct(p_bal, 0.5, prior)   # balanced は割合 0.5 で学習したのと同じ
```

冒頭の図で緑の線が、この `p_fix` です。予測確率の平均は、`balanced` のままでは 0.207 で、テストで陽性が占める 0.023 の 9 倍ありました。補正すると 0.022 になります。

同じ式は、分類器の出力を新しい事前確率に合わせる方法として、Saerens らの [2002 年の論文](https://doi.org/10.1162/089976602753284446)に書かれています。ロジスティック回帰の切片を直す同じ考え方は、King と Zeng が[珍しい事象のデータ](https://doi.org/10.1093/oxfordjournals.pan.a004868)について 2001 年に示しました。

### 補正と校正の比較

確率を戻す手段は、オッズで直す補正のほかに、正解の付いたデータで確率と実際の割合を合わせ直す[確率の校正](../../ml/probability-calibration/)があります。

冒頭で触れたアンダーサンプリングも、陽性を半分にするという点で `balanced` と同じことをします。テストの 5592 件で、確率の正しさを測る log loss と、確率の平均を並べました。log loss は、陽性に低い確率、陰性に高い確率を付けるほど大きくなる値で、詳しくは[損失関数](../../ml/loss-functions/)で説明しています。

| 学習のやり方と後処理 | 後処理に要るもの | log loss | 確率の平均 |
|---|---|---:|---:|
| 重み無し | なし | 0.0577 | 0.0239 |
| `balanced` のまま | なし | 0.2822 | 0.2068 |
| `balanced` を補正 | 学習データで陽性が占める割合 | 0.0603 | 0.0220 |
| アンダーサンプリングのまま | なし | 0.3493 | 0.2336 |
| アンダーサンプリングを補正 | 学習データで陽性が占める割合 | 0.0732 | 0.0282 |
| `balanced` を校正 | 正解付きの校正用データ | 0.0594 | 0.0239 |

テストで陽性が占める割合は 0.0232 です。校正には [`CalibratedClassifierCV`](https://scikit-learn.org/stable/modules/generated/sklearn.calibration.CalibratedClassifierCV.html) の `method="sigmoid"` を使い、学習データの中で 5 分割して校正しました。

補正も校正も、log loss を `balanced` のままの 5 分の 1 ほどに戻しました。補正に要るのは、学習データで陽性が占める割合という 1 つの数だけです。校正は正解付きのデータを取り分ける必要がある代わりに、モデルの形が合っていないことによるずれも一緒に直します。

アンダーサンプリングを補正しても 0.0732 で、補正した `balanced` より悪いままでした。陰性を捨てた分だけ、陰性の特徴を学ぶ材料が減ったためと考えられます。`class_weight` やリサンプリングの効き方は[クラス不均衡への対処](../../ml/class-imbalance/)で比べています。

ROC-AUC は、6 通りとも 0.915〜0.927 でした。補正はオッズに同じ数を掛けるだけなので、確率の順位は変わりません。上位から順に見るだけの使い方なら、補正の有無で結果は変わりません。

本番で陽性が占める割合が学習時と違う時も、`prior_new` に本番の割合を入れれば同じ式で直せます。正解を使わずに本番の割合を推定する方法は、[データドリフト](../../mlops/data-drift/)で説明しています。

### 本番の割合を少ない正解から見積もる

本番の割合は、正解が少し届いた段階で見積もることがよくあります。200 件の正解に陽性が 8 件なら割合は 4% ですが、たまたま多かっただけかもしれません。ベイズの定理は、石灰化かどうかのような 2 つの仮説だけでなく、割合のように 0〜1 の連続した値を取る量にも使えます。この時は、割合 `θ` がどのあたりにありそうかを確率分布で表し、データを見る前の分布を事前分布（prior distribution）、見た後の分布を事後分布（posterior distribution）と呼びます。

割合の事前分布には、0〜1 の値を取る[ベータ分布](../probability-distributions/) `Beta(a, b)` がよく使われます。陽性 `h` 件と陰性 `t` 件の正解が届くと、事後分布は `Beta(a + h, b + t)` になります。尤度 `θ^h (1 - θ)^t` を事前分布の密度に掛けると、ベータ分布の指数に件数が足されるだけだからです。事前分布と事後分布が同じ形になる組を共役と呼びます。

<br>

`a` と `b` は、データを見る前に陽性と陰性をそれぞれ何件見たのと同じかを表し、`a + b` が事前分布の強さになります。テストから陽性 130 件と陰性 2470 件を選んで陽性の割合が 5% の本番を作り、正解が 1 件ずつ届くとして、3 つの事前分布から事後分布を求めました。

| 事前分布 | 置いた考え | 強さ `a + b` |
|---|---|---:|
| 一様分布 `Beta(1, 1)` | 0〜1 のどこも同じ高さとみなす | 2 件分 |
| `Beta(2.3, 97.7)` | 学習時の 2.3% を平均にする | 100 件分 |
| `Beta(23, 977)` | 学習時の 2.3% を平均にする | 1000 件分 |

一様分布も、陽性と陰性を 1 件ずつ見たのと同じ仮定を置いています。割合について何も仮定しない事前分布ではありません。

事後分布の幅は 95% 信用区間で表します。置いた事前分布とデータの下で、割合がその区間に入る事後確率が 95% になる区間で、コードでは [SciPy](https://scipy.org/) の [`scipy.stats.beta`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.beta.html) で事後分布を作り、その 2.5% 点と 97.5% 点を `ppf` で求めています。

```python
from scipy import stats

prod_n_neg = round(len(pos_idx) * 0.95 / 0.05)            # 陽性 130 件と陰性 2470 件で、割合 5% の本番を作る
prod = np.r_[pos_idx, rng.choice(neg_idx, prod_n_neg, replace=False)]
labels = y_te[rng.permutation(prod)]                     # 正解が届く順
priors = {"一様 Beta(1, 1)": (1.0, 1.0),
          "学習時の 2.3% を 100 件分 Beta(2.3, 97.7)": (2.3, 97.7),
          "学習時の 2.3% を 1000 件分 Beta(23, 977)": (23.0, 977.0)}
for name, (a, b) in priors.items():
    print(name)
    for n_ in [0, 200, 1600]:
        h = int(labels[:n_].sum())
        post = stats.beta(a + h, b + n_ - h)              # 事前 Beta(a, b) に陽性 h 件・陰性 n - h 件
        lo, hi = post.ppf([0.025, 0.975])
        print(f"  正解 {n_:>4} 件（陽性 {h:>2}）: 事後平均 {post.mean():.3f}  95% 信用区間 {lo:.3f}〜{hi:.3f}")
```

```text
一様 Beta(1, 1)
  正解    0 件（陽性  0）: 事後平均 0.500  95% 信用区間 0.025〜0.975
  正解  200 件（陽性  8）: 事後平均 0.045  95% 信用区間 0.021〜0.077
  正解 1600 件（陽性 83）: 事後平均 0.052  95% 信用区間 0.042〜0.064
学習時の 2.3% を 100 件分 Beta(2.3, 97.7)
  正解    0 件（陽性  0）: 事後平均 0.023  95% 信用区間 0.003〜0.060
  正解  200 件（陽性  8）: 事後平均 0.034  95% 信用区間 0.017〜0.058
  正解 1600 件（陽性 83）: 事後平均 0.050  95% 信用区間 0.040〜0.061
学習時の 2.3% を 1000 件分 Beta(23, 977)
  正解    0 件（陽性  0）: 事後平均 0.023  95% 信用区間 0.015〜0.033

  正解 1600 件（陽性 83）: 事後平均 0.041  95% 信用区間 0.034〜0.049
```

{{< figure src="bayes_beta.webp" alt="横軸は届いた正解の件数で、0・50・100・200・400・800・1600 の目盛りが等間隔に並ぶ（50 から先は倍ごと）。縦軸は陽性の割合の事後平均で、帯は 95% 信用区間。灰色の一様 Beta(1,1) は 50 件の 3.8% から 1600 件の 5.2% まで、5% の点線の近くを上下する。青の 100 件分の事前分布は 2.3% から上がり、1600 件で 5.0% に届く。赤の 1000 件分の事前分布は 2.3% の点線の近くからゆっくり上がり、1600 件でも 4.1% で、帯の上端は 5% の点線より下にある" caption="陽性の割合が 5% の本番で、正解が届くたびに求めた事後平均と 95% 信用区間" align="center" >}}

学習時の割合を 1000 件分の強さで置くと、1600 件の正解を見た後でも事後平均は 4.1% で、95% 信用区間の 3.4%〜4.9% は本番の 5% を含みません。ベータ分布の事後平均は、事前分布の平均と観測した割合に、それぞれ `a + b` と届いた件数で重みを付けた平均です。1000 件分の事前分布は、1600 件の正解に対しても 4 割近い重みを持ちます。

一様分布の事後平均は、正解 100 件で 4.9%、200 件で 4.5% でした。区間は件数とともに狭まりますが、事後平均は正解が届くたびに本番の 5% へ近づくわけではなく、たまたま陽性が少なく続けば離れます。

信用区間は、同じ手順を繰り返した時に区間が真の値を含む割合を表す信頼区間とは意味が違い、信頼区間は[仮説検定](../hypothesis-test/)で説明しています。

<br>

割合が変わったかもしれない時ほど、学習時の割合を強い事前分布にすると判断が遅れます。事前分布は過去のデータや専門知識から選び、強さを変えた候補で事後平均を並べて、結論が変わるかを見ておくと安全です。事前分布の重みが件数とともに薄まるのは、このベータ分布で成り立つことで、どのモデルでも同じとは限りません。

正解は 1 件ずつ足しても、まとめて足しても同じ事後分布になります。100 件分の事前分布に、最初の 200 件を 2 通りで足しました。

```python
a, b = 2.3, 97.7                                         # 100 件分の事前分布
for v in labels[:200]:                                   # 正解を 1 件ずつ足す
    a, b = a + v, b + 1 - v
print(f"1 件ずつ 200 回更新: Beta({a:.1f}, {b:.1f})、まとめて: Beta({2.3 + labels[:200].sum():.1f}, {97.7 + 200 - labels[:200].sum():.1f})")
```

```text
1 件ずつ 200 回更新: Beta(10.3, 289.7)、まとめて: Beta(10.3, 289.7)
```

どちらも同じ分布なので、事後分布はそのまま次の正解に対する事前分布として使えます。

ただし、同じ正解を 2 回足すと、根拠は増えていないのに区間だけが狭くなります。同じ患者から取った画像が何枚も入っている時のように、観測どうしが独立でないなら、その依存をモデルに入れる必要があります。次の節で扱うナイーブベイズで起きることも、同じ根拠を二重に数えることです。

<br>

ベータ分布と二項の尤度のような共役の組は、件数を足すだけで事後分布が求まります。一般のモデルでは周辺尤度の積分が解けないことが多く、[MCMC](https://doi.org/10.1093/biomet/57.1.97)（マルコフ連鎖モンテカルロ法）や[変分推論](https://doi.org/10.1080/01621459.2017.1285773)で近似します。[線形回帰](../../ml/linear-regression/)の重みに事前分布を置くベイズ線形回帰や、時系列の状態を観測のたびに更新する[カルマンフィルタ](https://doi.org/10.1115/1.3662552)も、同じ定理の上にあります。その時は、推論にかかる計算量と近似の誤差も見ておきます。

### ナイーブベイズと独立の仮定

ベイズの定理をそのまま分類器にしたのが、ナイーブベイズ（naive Bayes）です。クラス `y` ごとに `P(y) × P(x | y)` を計算し、値が大きいクラスを答えます。

ここまで使ったロジスティック回帰は、`P(y | x)` を直接学ぶ識別モデルです。ナイーブベイズは `P(x | y)` と `P(y)` を学び、ベイズの定理で `P(y | x)` に裏返す生成的分類器です。学び方は違いますが、どちらも `P(y)` に当たる部分が、学習データで陽性が占める割合を写します。ロジスティック回帰では主に切片がこれに当たり、冒頭で `balanced` が返した確率がずれたのも、この部分でした。

特徴が `d` 列ある時、`P(x | y)` を直接求めるのは難しいので、クラスが決まれば列どうしは独立だと仮定し、列ごとの `P(xj | y)` の積で代えます。

オッズの形で書くと、事後の対数オッズは「事前の対数オッズ + 列ごとの対数尤度比の和」です。1 列ごとに、石灰化かどうかの根拠が足されていきます。

2 つの列が同じことを測っていると、同じ根拠を 2 回足すことになります。極端な場合として、mammography の 6 列を 1〜8 回並べて [`GaussianNB`](https://scikit-learn.org/stable/modules/generated/sklearn.naive_bayes.GaussianNB.html) で学習しました。`GaussianNB` は、クラスごとに各列が正規分布に従うと仮定するナイーブベイズです。

```python
for k in [1, 2, 4, 8]:
    nb = GaussianNB().fit(np.tile(X_tr, k), y_tr)        # 6 列を k 回並べる
    p = nb.predict_proba(np.tile(X_te, k))[:, 1]
    stuck = ((p > 0.999) | (p < 0.001)).mean()
    hi = p >= 0.9
    print(f"同じ列を {k} 回: 0.001 未満か 0.999 超 {stuck:.1%}  log loss {log_loss(y_te, p):.3f}  "
          f"ROC-AUC {roc_auc_score(y_te, p):.3f}  0.9 以上 {hi.sum()} 件のうち陽性 {y_te[hi].mean():.1%}")
```

```text
同じ列を 1 回: 0.001 未満か 0.999 超 69.7%  log loss 0.285  ROC-AUC 0.913  0.9 以上 219 件のうち陽性 37.0%
同じ列を 2 回: 0.001 未満か 0.999 超 76.2%  log loss 0.669  ROC-AUC 0.913  0.9 以上 379 件のうち陽性 24.8%
同じ列を 4 回: 0.001 未満か 0.999 超 83.0%  log loss 1.395  ROC-AUC 0.911  0.9 以上 609 件のうち陽性 17.6%
同じ列を 8 回: 0.001 未満か 0.999 超 89.3%  log loss 2.468  ROC-AUC 0.906  0.9 以上 808 件のうち陽性 13.9%
```

{{< figure src="bayes_nb_copies.webp" alt="横軸は同じ 6 列を並べた回数 1、2、4、8 の 3 枚の折れ線。左は予測確率が 0.001 未満か 0.999 超に張り付いた割合で 70%、76%、83%、89% と増える。中央の log loss は 0.29、0.67、1.40、2.47 と増える。右の ROC-AUC は 0.913、0.913、0.911、0.906 とほぼ平ら" caption="GaussianNB に同じ 6 列を繰り返して渡した時の、張り付いた予測の割合・log loss・ROC-AUC" align="center" >}}

列を 8 回並べると、9 割の予測が 0.001 未満か 0.999 超に張り付き、log loss は 1 回だけの時に比べて 8 倍を超えました。ROC-AUC は 0.913 から 0.906 とほぼ変わりません。並べるたびに対数尤度比が k 倍になり、確率は両端へ押されますが、画像どうしの順位はほとんど入れ替わらないからです。確率 0.9 以上を付けた画像のうち、本当に石灰化だった割合は 37% から 14% に下がりました。

列を 1 回しか渡していない時でも、7 割の予測が張り付いています。重みを付けないロジスティック回帰では 22% なので、陽性が少ないことだけでは説明できません。`GaussianNB` の仮定は 2 つあり、mammography ではどちらも崩れています。

1 つは列どうしの独立です。陰性の画像に限っても、[相関係数](../correlation/)の絶対値が 0.89 になる列の組があり、その分だけ同じ根拠を二重に数えます。もう 1 つは、各列が正規分布に従うことです。[`QuantileTransformer`](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.QuantileTransformer.html) で各列の分布を正規分布の形に直してから渡すと、張り付きがどれだけ減るかを見ました。

```python
qt = QuantileTransformer(output_distribution="normal", random_state=0).fit(X_tr)
p_q = GaussianNB().fit(qt.transform(X_tr), y_tr).predict_proba(qt.transform(X_te))[:, 1]
```

```text
分位変換してから 1 回: 0.001 未満か 0.999 超 53.2%  log loss 0.529  ROC-AUC 0.897
```

張り付きは 70% から 53% に減りましたが、半分は残り、log loss は 0.285 から 0.529 に悪くなりました。列ごとの形を直しても、列どうしの関係は残るからだと考えられます。張り付きは 2 つの仮定の崩れが重なって起きていて、どちらか一方だけのせいにはできません。

<br>

scikit-learn の文書でも、[ナイーブベイズを説明したページ](https://scikit-learn.org/stable/modules/naive_bayes.html)に、分類器としては使えても確率の推定は悪く、`predict_proba` の値を真に受けないよう書かれています。

確率を何百回も掛けると、独立の仮定とは別に、小数で表せる範囲を下回って 0 になる問題も起きます。その時に log の和で計算する方法は、[対数・指数と log-odds](../log-exp-logodds/) で説明しています。

### predict_proba を確率として使う前に

予測確率を確率の値として使うなら、最初に学習のやり方を見直します。`class_weight`、アンダーサンプリング、少数側の点を合成して増やす [SMOTE](https://doi.org/10.1613/jair.953) のように学習時に陽性が占める割合を変えていれば、モデルはその割合を事前確率として確率を返します。テストで予測確率の平均を出し、陽性が占める割合と比べると、冒頭の 0.207 と 0.023 のように 9 倍ずれていることがあります。

ずれていたら、学習時の割合が分かっているなら `correct` の式でオッズを直し、正解付きのデータを取り分けられるなら校正します。確率の順に上位から見るだけ、または閾値をテストで選び直すだけなら、順位は変わらないのでそのままでも困りません。ナイーブベイズの確率は、仮定が崩れると両端に寄りやすいので、順位として使うか、校正してから使います。

最後に、本番で陽性が占める割合を考えます。テストより陽性が少なければ、同じ閾値でも Precision は下がり、その値はベイズの定理で前もって計算できます。冒頭の図で、0.8〜0.9 を付けた 74 件のうち 11 件しか石灰化でなかったのは、モデルが 50% という事前確率で答えていたからでした。予測確率を読む時は、その確率がどの割合を前提にしているかを先に確認します。
