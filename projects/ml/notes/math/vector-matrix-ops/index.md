ベクトルは数を一列に並べたもので、2 つのベクトルの内積（inner product、dot product）は、同じ位置の成分を掛けて全て足した 1 つの数です。行列積は、この内積をまとめて計算する操作です。[線形回帰](../../ml/linear-regression/)の予測、[kNN](../../ml/knn/) の距離、大規模言語モデル（LLM）の注意機構、文書の検索と、機械学習の計算の多くは内積でできています。

内積は、2 つのベクトルが同じ向きを向くほど大きくなるので、似ている度合いとしてもよく使われます。内積を 2 つのベクトルの長さで割り、向きだけを比べる値はコサイン類似度（cosine similarity）と呼びます。では、内積が一番大きい相手は、一番似ている相手なのでしょうか。

[scikit-learn](https://scikit-learn.org/stable/) に同梱の [digits](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_digits.html) は、手書きの数字 1797 枚を 8 × 8 の画素の濃さ（0〜16）で表したデータで、1 枚が 64 個の数のベクトルです。1797 枚それぞれについて、内積が一番大きい別の画像と、コサイン類似度が一番大きい別の画像を探しました。

{{< figure src="vmo_cover.webp" alt="左に赤枠で 1747 番の画像を大きく置き、数字の 1 で、長さ 76.9 は全画像で最大と書いている。右は 5 列 3 段の画像の表で、上の段は問い合わせの画像（数字 4、7、8、5、9）。中の段は内積で 1 位の画像で、5 列とも同じ 1747 番の 1 が赤枠で並ぶ。下の段はコサイン類似度で 1 位の画像で、数字 4、7、8、5 が緑枠で並び、9 の問い合わせに 5 を選んだ 5 列目だけが灰色の枠" caption="内積とコサイン類似度で、一番近いと選ばれた画像" align="center" >}}

内積で選ぶと、1797 枚のうち 166 枚が同じ 1747 番の「1」を一番近いと答えました。1747 番を選んだ 166 枚のうち、85 枚は 4、30 枚は 7、28 枚は 8 です。1747 番は、64 個の数の 2 乗和の平方根で測る長さが全画像で一番大きい画像でした。一番近い画像が同じ数字だった割合は、コサイン類似度の 98.9% に対して、内積では 72.1% に下がります。NumPy は、どちらの計算もエラーも警告も出さずに返します。

<br>

本記事では、ML の説明に出てくる内積と行列積を自分で計算して確認したい人と、NumPy や scikit-learn で手元のデータに使う人に向けて、次の疑問に答えます。

- 内積は、2 つのベクトルの何を測るのか。
- 内積・コサイン類似度・距離で、一番近い相手はどう変わるのか。
- 行列とベクトルの積、行列積は、何をまとめて計算するのか。
- 形の違う配列を引くと、NumPy は何を返すのか。
- 同じ式でも、掛ける順で計算量はどれだけ変わるのか。

実験は [NumPy](https://numpy.org/) 2.5.4 と scikit-learn 1.9.1 で行いました。図を描く処理も含めた完全なコードは [vector-matrix-ops_gen.py](https://github.com/nao1215/debimate/blob/main/projects/ml/scripts/notes/vector-matrix-ops_gen.py) にあります。

### ベクトルの足し算とスカラー倍

1 件のデータの特徴量も、モデルの重みや[勾配](../partial-derivative-gradient/)も、数の並びなのでベクトルで表します。同じ長さのベクトル同士の足し算・引き算は、同じ位置の成分同士を計算します。スカラー倍は、全ての成分を同じ数 `k` 倍する計算です。

```python
a = np.array([3, 1])
b = np.array([1, 2])
v = np.array([2, 1])
print("a + b:", a + b, " a - b:", a - b)
print("1.5 * v:", 1.5 * v, " -1 * v:", -1 * v, " 0 * v:", 0 * v)
```

```text
a + b: [4 3]  a - b: [ 2 -1]
1.5 * v: [3.  1.5]  -1 * v: [-2 -1]  0 * v: [0 0]
```

{{< figure src="vmo_vector_basics.webp" alt="左は足し算で、青い a = (3, 1) の矢印の先に緑の b = (1, 2) を継ぎ足すと、原点からその先への赤い矢印が a + b = (4, 3) になる。右はスカラー倍で、v = (2, 1) に対し、1.5 * v = (3, 1.5) は同じ向きで 1.5 倍の長さ、-1 * v = (-2, -1) は逆向きで同じ長さ、0 * v は原点の点 (0, 0)" caption="ベクトルの足し算とスカラー倍" align="center" >}}

`a + b` は、`a` の矢印の先に `b` の矢印を継ぎ足した先を指します。スカラー倍では、`k` が正なら向きは変わらずに長さだけが変わり、負なら向きが反転し、0 なら全ての成分が 0 の零ベクトルになります。NumPy の `+` `-` `*` はこの成分ごとの計算で、形の違う配列同士で使った時の振る舞いは、後のブロードキャストの節で扱います。

### 内積は長さと角度の積

2 つのベクトル `a = (a1, a2, ..., an)` と `b = (b1, b2, ..., bn)` の内積は `a · b = a1 b1 + a2 b2 + ... + an bn` です。NumPy では `a @ b` か `np.dot(a, b)` で求めます。ベクトルの長さ（ノルム）は自分自身との内積の平方根 `||a|| = sqrt(a · a)` で、`np.linalg.norm(a)` が返す値です。

この長さは L2 ノルムと呼ばれ、ほかに成分の絶対値の和を取る L1 ノルム、絶対値の最大を取る L∞ ノルムもあります。[正則化](../../ml/regularization/)は、重みの L1 ノルムや L2 ノルムの 2 乗を損失に足して、重みが大きくなりすぎるのを防ぎます。L1 は一部の重みをちょうど 0 にした解を作りやすく、L2 は重みを 0 にはせずに全体を小さく抑えます。

同じ内積は、2 つのベクトルの間の角度 `θ` を使うと `a · b = ||a|| ||b|| cos θ` とも書けます。コサイン類似度は、この式を長さで割った `cos θ` で、同じ向きなら 1、直交なら 0、逆向きなら -1 です。内積の符号も `cos θ` と同じで、角度が 90 度未満なら正、90 度より大きければ負になります。

基準のベクトル `q` に対して、向きが 10 度しか違わない短い `a` と、50 度違う長い `b` の内積を比べました。

```python
def polar(r, deg):
    return r * np.array([np.cos(np.radians(deg)), np.sin(np.radians(deg))])


q = polar(2.0, 20)
a = polar(1.5, 30)   # q との角度 10 度、短い
b = polar(4.0, 70)   # q との角度 50 度、長い
for name, v in [("a", a), ("b", b)]:
    cos = q @ v / (np.linalg.norm(q) * np.linalg.norm(v))
    print(f"{name}: 長さ {np.linalg.norm(v):.1f}  角度 {np.degrees(np.arccos(cos)):.0f} 度  "
          f"内積 {q @ v:.2f}  コサイン類似度 {cos:.3f}")
```

```text
a: 長さ 1.5  角度 10 度  内積 2.95  コサイン類似度 0.985
b: 長さ 4.0  角度 50 度  内積 5.14  コサイン類似度 0.643
```

{{< figure src="vmo_dot_geometry.webp" alt="原点から黒い q（長さ 2.0）、緑の a（長さ 1.5、q との角度 10 度）、赤い b（長さ 4.0、q との角度 50 度）の 3 本の矢印。a と b の先から q の向きの破線へ垂線を下ろし、影の先を点で示す。b の影は a の影より長い。a は内積 2.95、コサイン類似度 0.98、b は内積 5.14、コサイン類似度 0.64" caption="向きの近い a より、長い b の方が q との内積は大きい" align="center" >}}

内積は、`q` の長さに、相手を `q` の向きに落とした影の長さを掛けた値です。角度が 90 度を超えると影は `q` と逆向きに落ち、その長さを負として数えるので、内積は負になります。

`b` は向きが 50 度ずれていても長いので、影が `a` より長くなり、内積は `a` の 2.95 に対して 5.14 になりました。コサイン類似度は長さで割って向きだけを比べるので、`a` の 0.985 が `b` の 0.643 を上回ります。

冒頭の 1747 番は、この `b` と同じ立場です。画素の濃い部分が多く、長さが全画像で一番大きいので、向きが少しずれた相手との内積でも、他の画像より大きくなります。

### 内積・コサイン類似度・ユークリッド距離

似ている度合いには、内積とコサイン類似度に加えて、2 点の間の直線の長さであるユークリッド距離 `||a - b||` もよく使われます。scikit-learn の [kNN](../../ml/knn/) が既定で使う距離です。3 つの間には次の関係があります。

```text
||a - b||² = ||a||² + ||b||² - 2 (a · b)
```

全てのベクトルの長さを 1 に揃えると、右辺は `2 - 2 cos θ` になり、3 つの指標は同じ順位を返します。digits の画像は長さが揃っておらず、[中央値](../median/)の 62.1 に対して最大は 76.9 です。1797 枚の全ての組で 3 つの指標を求め、一番近い画像を選びました。

```python
digits = load_digits()
X = digits.data            # 1797 枚 × 64 画素（0〜16 の濃さ）
y = digits.target

G = X @ X.T                                    # 全ての組の内積（1797 × 1797）
norm = np.linalg.norm(X, axis=1)               # 各画像の長さ
cos_sim = G / np.outer(norm, norm)             # コサイン類似度
dist2 = norm[:, None] ** 2 + norm[None, :] ** 2 - 2 * G  # ユークリッド距離の 2 乗

nearest = {}
for name, S, larger in [("内積", G, True), ("コサイン類似度", cos_sim, True),
                        ("ユークリッド距離", dist2, False)]:
    S = S.astype(float).copy()
    np.fill_diagonal(S, -np.inf if larger else np.inf)   # 自分自身は除く
    nn = S.argmax(axis=1) if larger else S.argmin(axis=1)
    nearest[name] = nn
    hits = np.bincount(nn, minlength=len(X))           # 一番近いと選ばれた回数
    print(f"{name:<10}: 一番近い画像が同じ数字 {np.mean(y[nn] == y):.1%}  "
          f"一番近いと選ばれた画像 {np.count_nonzero(hits)} 枚  "
          f"最多 {hits.max()} 回（{hits.argmax()} 番、数字 {y[hits.argmax()]}）")
```

```text
内積        : 一番近い画像が同じ数字 72.1%  一番近いと選ばれた画像 225 枚  最多 166 回（1747 番、数字 1）
コサイン類似度   : 一番近い画像が同じ数字 98.9%  一番近いと選ばれた画像 1065 枚  最多 6 回（812 番、数字 0）
ユークリッド距離  : 一番近い画像が同じ数字 98.8%  一番近いと選ばれた画像 1103 枚  最多 6 回（79 番、数字 0）
```

次の図は、横軸に各画像の長さ、縦軸に他の画像から一番近いと選ばれた回数を取ったものです。

{{< figure src="vmo_norm_hits.webp" alt="2 枚の散布図。横軸は画像の長さで 47 から 77、縦軸は他の画像から一番近いと選ばれた回数。左の内積では、長さ 65 未満の画像はほぼ 0 回で、長さが 70 を超える画像だけが数十回選ばれ、右端の 1747 番（数字 1）は 166 回。一番近いと選ばれた画像は 225 枚、同じ数字を選んだ割合は 72.1%。右のコサイン類似度では、全ての長さで 0〜6 回に収まり、選ばれた画像は 1065 枚、同じ数字を選んだ割合は 98.9%" caption="画像の長さと、一番近いと選ばれた回数" align="center" >}}

内積では、一番近いと選ばれた画像は 1797 枚のうち 225 枚しかなく、長い画像ばかりが一番近い相手になります。コサイン類似度では、選ばれる回数は長さによらず 6 回以下に収まりました。数字ごとに見ると、内積で同じ数字を選べた割合は 4 が 41%、8 が 36% で、1 は長い 1747 番を一番近い相手にするので 100% です。

何度も近傍に選ばれる点はハブ（hub）と呼ばれます。Radovanović 氏らの [2010 年の論文](https://jmlr.org/papers/v11/radovanovic10a.html)は、[次元の高い](../../ml/curse-of-dimensionality/)データでは距離を使ってもハブが現れることを報告しています。digits の内積の場合、原因はもっと単純で、長さです。

#### 指標の選び方

次の表に出てくる埋め込み（embedding）は、文や画像をモデルに通して得る数の並びで、意味の近いもの同士が近いベクトルになるように作られます。注意機構は、LLM が文中のどの語をどれだけ参照するかを語のベクトル同士の内積で決める仕組みです。長さの扱いで 3 つの指標を並べると、次の通りです。

| 指標 | 長さの扱い | 使われる所 |
|---|---|---|
| 内積 | 長いほど大きい | 線形モデルの予測、注意機構、長さ 1 に揃えた埋め込み |
| コサイン類似度 | 長さで割るので効かない | 文書や埋め込みの近さ |
| ユークリッド距離 | 長さの差も距離に入る | kNN の既定、[k-means](../../ml/k-means/) |

内積そのものが悪いわけではありません。線形回帰の `X @ w` では、値の大きさがそのまま予測に効くべきなので、長さを捨てません。LLM の注意機構も、[KV キャッシュのノート](/notes/generative-ai/kv-cache/)で説明しているとおり、内積で配分を決めます。長さに意味が無く、向きだけを比べたい時に、内積をそのまま似ている度合いに使うと、冒頭の 1747 番のような偏りが出ます。

向きだけを比べるなら、先に [`sklearn.preprocessing.normalize`](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.normalize.html) で全ての行の長さを 1 に揃えます。揃えた後の内積はコサイン類似度に一致します。ただし、全ての成分が 0 のベクトルは長さが 0 で、角度を決められないので、コサイン類似度も求まりません。`normalize` はそのような行を 0 のまま返します。

ライブラリが長さを揃えて返す例もあります。文書を単語の重みのベクトルに直す scikit-learn の [`TfidfVectorizer`](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html) は、既定の `norm="l2"` で長さを 1 に揃えて返します。質問に近い文書を探して LLM に渡す [RAG](/notes/generative-ai/rag/) の検索も、長さを 1 に揃えてから内積を取っています。

### 行列とベクトルの積、行列積

行列 `A` とベクトル `x` の積 `A @ x` は、`A` の各行と `x` の内積を縦に並べたベクトルです。データを 1 行 1 サンプルの行列 `X` に並べ、重み `w` を掛けた `X @ w` は、全てのサンプルについて「特徴量 × 重み」の和を一度に求めます。線形回帰の予測はこの形に切片 `b` を足した `X @ w + b` で、[ロジスティック回帰](../../ml/logistic-regression/)はこの値をシグモイド関数に通します。

重みを 1 列ではなく行列 `W` にすると、ニューラルネットワークの層のように、複数の出力を `X @ W` でまとめて求められます。

`X` の形が `(n, d)` の時、`w` が 1 次元の配列 `(d,)` なら `X @ w` も 1 次元の `(n,)` になり、`w` を `(d, 1)` の列にすると `(n, 1)` になります。digits の `X` で形を出しました。

```python
w = np.ones(X.shape[1])                  # 64 個の重み、形は (64,)
print("X @ w の形:", (X @ w).shape, " X @ w.reshape(-1, 1) の形:", (X @ w.reshape(-1, 1)).shape)
```

```text
X @ w の形: (1797,)  X @ w.reshape(-1, 1) の形: (1797, 1)
```

値は同じでも、この 2 つの形の違いは後のブロードキャストの節で効いてきます。

行列積 `A @ B` の `(i, j)` の値は、`A` の `i` 行目と `B` の `j` 列目の内積です。そのため、`A` の列の数と `B` の行の数が等しい必要があり、`(n, k)` と `(k, m)` の積は `(n, m)` になります。`k` が合わなければ、[`np.matmul`](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html) は `ValueError` を出します。`@` は `np.matmul` と同じ計算です。

画像生成や LLM の追加学習で使う [LoRA](/notes/generative-ai/lora/) は、この形の規則を使い、重みの差分を `(n, k)` と `(k, m)` の 2 つの細長い行列の積で表します。内側の `k` を小さく取るので、学習する数が `n × m` から `(n + m) × k` に減ります。

前の節の `G = X @ X.T` は、`(1797, 64)` と `(64, 1797)` の積で、`(i, j)` の値が `i` 枚目と `j` 枚目の画像の内積になります。同じ表を 1 組ずつの内積で作る二重ループと比べました。

```python
t_mat = best_time(lambda: X @ X.T)
t0 = time.perf_counter()
G_loop = np.empty((len(X), len(X)))
for i in range(len(X)):
    for j in range(len(X)):
        G_loop[i, j] = X[i] @ X[j]          # 1 組ずつ内積を取る
t_loop = time.perf_counter() - t0
print(f"X @ X.T       : {t_mat * 1e3:.1f} ms")
print(f"二重ループ    : {t_loop * 1e3:.0f} ms（{t_loop / t_mat:.0f} 倍）  結果が一致: {np.allclose(G_loop, G)}")
```

```text
X @ X.T       : 3.2 ms
二重ループ    : 5992 ms（1897 倍）  結果が一致: True
```

`best_time` は、関数を 1 回空で呼んでから 50 回計り、一番短い時間を返す補助関数です。

{{< figure src="vmo_gram.webp" alt="左から、縦長の X（1797 × 64）の i 行目、横長の X.T（64 × 1797）の j 列目を青く塗り、@ と = でつないだ先の正方形の X @ X.T（1797 × 1797）の (i, j) のマスを赤く塗っている。赤いマスの値は i 行目と j 列目の内積。見出しは、1 回の行列積で 1797 × 1797 組の内積を求める（3.2 ms。1 組ずつの二重ループは 6.0 秒）" caption="X @ X.T の 1 マスは、1 組の画像の内積" align="center" >}}

1797 × 1797 の 323 万組の内積が、行列積なら 3.2 ms、二重ループなら 6.0 秒でした。NumPy の行列積は、行列の計算を速くするための BLAS という部品（ここでは [OpenBLAS](https://www.openblas.net/) 0.3.34）を呼び、Python の 1 回ずつの呼び出しを省きます。時間は手元の機械での値で、比は環境で変わります。[kNN のノート](../../ml/knn/)で触れている総当たりの近傍探索も、この行列積で距離をまとめて求めます。

#### 行列とベクトルの積は平面の変換

2 次元のベクトルに 2 × 2 の行列を掛けると、平面の点が別の点に移ります。30 度回す行列 `R`、横に 2 倍に伸ばす行列 `S`、その 2 つを掛けた `S @ R` で、格子の全ての点を移しました。

```python
th = np.radians(30)
R = np.array([[np.cos(th), -np.sin(th)], [np.sin(th), np.cos(th)]])  # 30 度回す
S = np.array([[2.0, 0.0], [0.0, 1.0]])                              # 横に 2 倍
g = np.linspace(-1, 1, 5)
lines = [np.column_stack([g, np.full(5, c)]) for c in g] + [np.column_stack([np.full(5, c), g]) for c in g]
e1, e2 = np.array([1.0, 0.0]), np.array([0.0, 1.0])
print("S @ R の 1 列目と 2 列目:", np.round(S @ R, 3).T.tolist())
print("S @ (R @ e1) と (S @ R) @ e1:", np.round(S @ (R @ e1), 3), np.round((S @ R) @ e1, 3))
```

```text
S @ R の 1 列目と 2 列目: [[1.732, 0.5], [-1.0, 0.866]]
S @ (R @ e1) と (S @ R) @ e1: [1.732 0.5  ] [1.732 0.5  ]
```

{{< figure src="vmo_transform.webp" alt="4 枚の格子の図。1 枚目は -1 から 1 の正方形の格子と、赤い (1, 0)、緑の (0, 1) の矢印。2 枚目の R は格子全体が 30 度回る。3 枚目の S は横に 2 倍に伸びる。4 枚目の S @ R は回してから横に伸ばした平行四辺形の格子になる。図の下に、赤い矢印は (1, 0) の、緑の矢印は (0, 1) の移った先で、それぞれ行列の 1 列目と 2 列目に等しいと書いている" caption="行列を掛けると、格子は回り、伸びる" align="center" >}}

まっすぐな線はまっすぐなまま、原点は原点のまま移ります。このような移し方を線形変換と呼びます。`(1, 0)` が移る先は行列の 1 列目、`(0, 1)` が移る先は 2 列目なので、行列の列を見れば変換の形が分かります。

[PCA](../../ml/pca/) で主成分の座標を求める計算も、平均を引いたデータにこの形の行列を掛ける計算です。全ての主成分を残すと回転、向きによっては反転を含む変換になり、一部だけ残すと主成分の方向への射影になります。

ただし、全ての変換が元に戻せるわけではありません。次の `P` は平面の点を横軸の上に潰す射影の行列で、`(1, 2)` も `(1, -3)` も同じ `(1, 0)` に移ります。移った先から元の点を決められないので、`P` には逆行列がありません。

```python
P = np.array([[1.0, 0.0], [0.0, 0.0]])   # 平面の点を横軸の上に潰す
print("P @ (1, 2) と P @ (1, -3):", P @ np.array([1.0, 2.0]), P @ np.array([1.0, -3.0]))
try:
    np.linalg.inv(P)
except np.linalg.LinAlgError as e:
    print("np.linalg.inv(P):", type(e).__name__, e)
```

```text
P @ (1, 2) と P @ (1, -3): [1. 0.] [1. 0.]
np.linalg.inv(P): LinAlgError Singular matrix
```

`R` で回してから `S` で伸ばす変換は、`S @ (R @ x)` と書いても、先に 2 つの行列を掛けた `(S @ R) @ x` と書いても同じ点に移ります。一方で、掛ける順を入れ替えた `R @ S` は、伸ばしてから回す変換で、1 列目が `(1.732, 1.0)` になり `S @ R` の `(1.732, 0.5)` と一致しません。

行列積では、一般に `A @ B` と `B @ A` は別の行列です。`(2, 3)` と `(3, 4)` の積のように、順を入れ替えると形が合わず計算できない組もあります。

掛ける順はそのままで括弧の位置だけが違う `S @ (R @ x)` と `(S @ R) @ x` は、答えが同じでも、どちらを先に計算するかで手間が大きく変わります。これは後の「掛ける順と計算量」の節で扱います。

<br>

括弧の位置を変えてよいので、線形変換を何回重ねても、先に行列同士を掛けた 1 つの行列にまとまります。ニューラルネットワークが層の間に非線形な[活性化関数](../../ml/activation-functions/)を挟むのは、層を重ねても 1 つの行列で済む変換にならないようにするためです。

### 形が合わない時のブロードキャスト

`@` は内側の大きさが合わなければエラーを出しますが、`-` や `*` のような成分ごとの演算は、形が違ってもエラーを出さないことがあります。NumPy の[ブロードキャスト](https://numpy.org/doc/stable/user/basics.broadcasting.html)は、2 つの配列の形を右の軸から揃え、大きさが 1 の軸や足りない軸は相手に合わせて繰り返したものとして計算します。

この規則に出会いやすいのが、目的変数の形です。pandas で `df[["target"]]` のように列を 2 重の括弧で選ぶと 1 列の表になり、目的変数を 1 次元で渡したつもりでも形は `(n, 1)` になります。[`LinearRegression`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LinearRegression.html) に 1 列の表を渡して学習すると、予測も `(n, 1)` で返ります。形が `(442,)` の 1 次元の配列と、`(442, 1)` の 1 列の配列を引くと、ブロードキャストの規則で `(442, 442)` の行列になります。scikit-learn の [diabetes](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_diabetes.html) で、目的変数を 1 列の表として線形回帰に渡し、予測の誤差を NumPy で計算しました。pandas は使わず、`reshape(-1, 1)` で `df[["target"]]` と同じ `(442, 1)` の形を作っています。

```python
diabetes = load_diabetes()
Xd, yd = diabetes.data, diabetes.target               # 442 人 × 10 列、yd の形は (442,)
model = LinearRegression().fit(Xd, yd.reshape(-1, 1))  # 目的変数を 1 列の表で渡した
pred = model.predict(Xd)                               # 形は (442, 1)
diff = yd - pred
print("yd の形:", yd.shape, " pred の形:", pred.shape, " yd - pred の形:", diff.shape)
mse_wrong = np.mean((yd - pred) ** 2)
mse_right = np.mean((yd - pred.ravel()) ** 2)
print(f"形を揃えずに計算した MSE: {mse_wrong:,.0f}")
print(f"pred.ravel() で揃えた MSE: {mse_right:,.0f}")
print(f"mean_squared_error         : {mean_squared_error(yd, pred):,.0f}")
print(f"yd の分散（平均で予測した時の MSE）: {yd.var():,.0f}")
```

```text
yd の形: (442,)  pred の形: (442, 1)  yd - pred の形: (442, 442)
形を揃えずに計算した MSE: 9,000
pred.ravel() で揃えた MSE: 2,860
mean_squared_error         : 2,860
yd の分散（平均で予測した時の MSE）: 5,930
```

{{< figure src="vmo_broadcast.webp" alt="左は形の図で、上に横長の yd（形 (442,)）、左に縦長の pred（形 (442, 1)）があり、その間の正方形が yd - pred（形 (442, 442)）で、(i, j) = yd[j] - pred[i]、442 × 442 = 195,364 個の差と書いている。右は diabetes の線形回帰の MSE の棒グラフで、形を揃えた MSE が 2,860、平均で予測した MSE（分散）が 5,930、形を揃えない MSE が 9,000" caption="(442,) と (442, 1) を引くと、442 × 442 の差の表になる" align="center" >}}

`yd - pred` の `(i, j)` は、`j` 人目の正解と `i` 人目の予測の差で、関係の無い組の差まで 19 万個以上を平均しています。MSE（平均二乗誤差）は 2,860 から 9,000 に増え、全員を平均値で予測した時の 5,930 より悪く見えます。[回帰の評価指標](../../ml/regression-metrics/)の R² に直すと、0.52 のはずのモデルが負の値になります。

scikit-learn の [`mean_squared_error`](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_squared_error.html) は形を調べてから揃えるので、同じ `pred` でも 2,860 を返しました。誤差を NumPy で自分で書く時は、引く前に 2 つの `shape` を出すか、`pred.ravel()` で 1 次元に揃えます。

同じように、`X @ w` のつもりで `X * w` と書くと、各列に重みを掛けただけの `(442, 10)` が返り、行ごとの和は取られません。

### 掛ける順と計算量

行列積は、`(A @ B) @ C` と `A @ (B @ C)` が同じ答えになります。平面の変換で `S @ (R @ e1)` と `(S @ R) @ e1` が同じ点に移ったのと同じ性質です。ただし、Python の `@` は、`@` を足した提案の文書 [PEP 465](https://peps.python.org/pep-0465/) で左から順に計算すると決まっていて、`X @ X.T @ v` は先に `X @ X.T` を作ります。

`X @ X.T @ v` は、近い画像を探した時の `G = X @ X.T` の各行に重み `v` を掛けて足したもので、画像ごとに、全画像との内積を重み付きで足した値になります。digits の `X` で、1797 枚分の重み `v` を掛ける 2 通りの順を比べました。`(n, k)` と `(k, m)` の積は、掛け算を `n × k × m` 回行います。

```python
v = np.random.default_rng(0).normal(size=len(X))      # 1797 個の重み
left = X @ X.T @ v            # Python の @ は左から: (X @ X.T) @ v
right = X @ (X.T @ v)
print("2 つの結果が一致:", np.allclose(left, right))
t_left = best_time(lambda: X @ X.T @ v)
t_right = best_time(lambda: X @ (X.T @ v))
t_multi = best_time(lambda: np.linalg.multi_dot([X, X.T, v]))
t_gram = best_time(lambda: X @ X.T)                 # 途中の X @ X.T だけ
n, d = X.shape
mul_left = n * d * n + n * n          # X @ X.T と、その結果 @ v の掛け算の回数
mul_right = d * n + n * d             # X.T @ v と、X @ その結果
print(f"(X @ X.T) @ v : {t_left * 1e3:.2f} ms  掛け算 {mul_left:,} 回")
print(f"X @ (X.T @ v) : {t_right * 1e3:.3f} ms  掛け算 {mul_right:,} 回")
print(f"multi_dot     : {t_multi * 1e3:.3f} ms")
print(f"途中の X @ X.T: {t_gram * 1e3:.2f} ms")
print(f"時間の比 {t_left / t_right:.0f} 倍、掛け算の回数の比 {mul_left / mul_right:.0f} 倍")
```

```text
2 つの結果が一致: True
(X @ X.T) @ v : 6.03 ms  掛け算 209,898,585 回
X @ (X.T @ v) : 0.027 ms  掛け算 230,016 回
multi_dot     : 0.119 ms
途中の X @ X.T: 3.17 ms
時間の比 221 倍、掛け算の回数の比 913 倍
```

{{< figure src="vmo_chain.webp" alt="2 枚の対数目盛の棒グラフ。左は掛け算の回数で、途中に 1797 × 1797 を作る (X @ X.T) @ v が 209,898,585 回、途中に 64 個を作る X @ (X.T @ v) が 230,016 回。右はかかった時間（50 回の最短）で、6.03 ms と 0.027 ms。見出しは、同じ答えでも、掛ける順で掛け算は 913 倍、時間は 221 倍違う" caption="掛ける順を変えただけで、掛け算は 913 倍違う" align="center" >}}

左から計算すると、途中で 1797 × 1797 の行列を作るので、掛け算は約 2 億回です。先に `X.T @ v` を計算すると、途中は 64 個の数で済み、掛け算は 23 万回、913 分の 1 になりました。時間の差も 221 倍あり、答えは同じです。

掛け算の回数を内訳に分けると、どこで増えたかが分かります。

| 計算 | 掛け算の回数 |
|---|---|
| `X @ X.T` | 206,669,376 回 |
| できた 1797 × 1797 の行列 `@ v` | 3,229,209 回 |
| `X @ (X.T @ v)` 全体 | 230,016 回 |

左から計算した時の掛け算は、ほとんどが途中の `X @ X.T` です。1797 × 1797 個の 8 バイトの数で、途中の行列は約 26 MB あります。左から計算すると、使い道が `v` との積だけの大きな行列を作ることになります。

一方、時間の比は 221 倍で、掛け算の回数の比 913 倍ほどには開きませんでした。時間は掛け算の回数だけでは決まらず、手元の機械で測り直すと、この比は 200〜900 倍ほどの間で動きました。

順を自分で考えない時は、[`np.linalg.multi_dot`](https://numpy.org/doc/stable/reference/generated/numpy.linalg.multi_dot.html) に行列を並べて渡すと、掛け算の少ない順を選びます。順を選ぶ手間の分だけ手で括弧を付けた形より遅く、0.119 ms でしたが、左から計算するより 50 倍以上速くなりました。式がベクトルで終わる時は、ベクトルを含む積から先に計算するのが基本です。

<br>

手間を減らす工夫は、掛ける順のほかにもあります。式に逆行列が出てくる時は、`np.linalg.inv` で逆行列を作ってから掛けるより、[`np.linalg.solve`](https://numpy.org/doc/stable/reference/generated/numpy.linalg.solve.html) で方程式を直接解く方が手間も丸めの誤差も少なく済みます。線形回帰のような最小二乗の問題なら、特異値分解を使う [`np.linalg.lstsq`](https://numpy.org/doc/stable/reference/generated/numpy.linalg.lstsq.html) で解く方法もあります。

大半が 0 の大きな行列なら、[SciPy の疎行列](https://docs.scipy.org/doc/scipy/reference/sparse.html)で 0 以外の値だけを持つと、メモリ使用量も掛け算の回数も減ります。

### 内積を使う前に見ること

内積を似ている度合いに使う前に、`np.linalg.norm(X, axis=1)` で各行の長さを出します。長さは単位でも変わり、身長を m から cm に直すだけで、その列が長さの大半を占めるようになります。列ごとの単位が揃っていない時は、先に[標準化](../../ml/standardization/)で大きさを揃えます。digits のように長さがばらつき、その長さに意味が無いなら、`normalize` で長さを 1 に揃えてから内積を取ります。揃えた内積はコサイン類似度に一致し、冒頭の図の下の段では 5 列のうち 4 列で同じ数字を選びます。

長さに意味がある場合は内積のまま使いますが、上位に同じ相手ばかりが出ていないかを `np.bincount` で数えます。冒頭の実験では、1797 枚のうち 166 枚が 1747 番を選び、一番近いと選ばれた画像は 225 枚しかありませんでした。1 つの相手が何十回も選ばれていたら、それは似ているからではなく、長いからです。

<br>

行列の計算を自分で書く時は、成分ごとに引く前に 2 つの `shape` を並べて出し、`(n,)` と `(n, 1)` が混ざっていないかを見ます。行と列を取り違えても、大きさがたまたま合えば計算できてしまうので、どの軸がサンプルでどの軸が特徴量かも合わせて見ます。式が `X @ X.T @ v` のようにベクトルで終わるなら、`X @ (X.T @ v)` のようにベクトルを含む積に括弧を付けるか `multi_dot` を使います。どの間違いも、NumPy はエラーを出さずにそれらしい数を返すので、冒頭の 1747 番の画像のように、返った結果の偏りを見るまで分かりません。
