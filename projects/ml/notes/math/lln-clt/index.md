大数の法則（law of large numbers、LLN）は、同じ分布から独立に取った値を平均すると、件数を増やすほど、平均が[期待値](../expectation/)から大きく外れる確率が小さくなるという定理です。平均が標本ごとにどれだけ揺れるかを表す値は、標準誤差と呼びます。中心極限定理（central limit theorem、CLT）は、平均と期待値のずれを標準誤差で割った値が、件数が大きい時に平均 0、標準偏差 1 の正規分布に近づくという定理です。

2 つの定理を組み合わせると、手元の `n` 件から「平均 ± 約 2 × 標準誤差」の区間を作れ、正規分布への近似がよく効いていれば、この区間は真の平均を 95% の割合で含みます。この区間を 95% 信頼区間と呼びます。

この区間の説明では、「`n` が 30 を超えれば、中心極限定理で平均は正規分布とみなせる」という目安をよく見かけます。件数を増やすほど区間は狭く、正確になるとも考えがちです。

そこで、[scikit-learn](https://scikit-learn.org/stable/) に同梱の [California Housing](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_california_housing.html) の 20640 地区を母集団とみなしました。母集団は、平均を知りたい対象の全体です。そこから重複を許して `n` 件を選んで平均の 95% 信頼区間を作り、20640 地区の平均を含むかを 10000 回数えました。

California Housing は、1990 年に米国で行われた国勢調査から、カリフォルニア州を block group と呼ぶ数百〜数千人の地区ごとにまとめたデータです。

所得の中央値（MedInc）では、`n = 30` で 94%、1000 で 95% と、狙いどおりに当たります。一方で、地区の人口を世帯数で割った 1 世帯あたりの人数（AveOccup）は、`n = 30` で 76%、`n = 1000` で 31% と、1000 件までは件数を増やすほど当たらなくなりました。左右の偏りを表す[歪度](../skewness/)は、MedInc が 1.6、AveOccup が 97.6 です。95% 近くに戻るのは、重複を許して選んだ 10 万件、つまり 20640 地区の約 5 倍でした。区間の計算に使った [SciPy](https://scipy.org/) も [NumPy](https://numpy.org/) も、警告は出しません。

テストデータの正解率、2 つの案を比べる A/B テストの売上、監視で見る応答時間の平均に ± を付ける時も、同じ計算をしています。AveOccup の崩れは、上位わずか 10 地区が作っていました。上位の数件が平均を大きく動かすデータなら、同じことが起こりえます。

### 期待値に近づく平均

`n` 件の値を平均したものを標本平均と呼び、`x_bar = (x1 + ... + xn) / n` と書きます。大数の法則は、値が互いに独立で同じ分布に従い（独立同分布、i.i.d.）、絶対値の期待値が有限で期待値 `μ` が定まれば、`n` を増やすと `x_bar` が `μ` に近づくと言っています。手元の値から出す平均と期待値の違いは、[平均](../mean/)で説明しています。

20640 地区から重複を許して 1 件ずつ選び、そこまでの平均を 10 万件まで追いました。重複を許すのは、選ぶたびに同じ分布から独立に取る状況にするためです。比べるために、期待値が存在しないコーシー分布の乱数も並べます。

実験は scikit-learn 1.9.1、NumPy 2.5.4、SciPy 1.18.1 で行い、本文の出力は、図を描く処理も含めた [lln-clt_gen.py](https://github.com/nao1215/debimate/blob/main/projects/ml/scripts/notes/lln-clt_gen.py) を上から実行した時の値です。

```python
data = fetch_california_housing()
names = data.feature_names
med_inc = data.data[:, names.index("MedInc")]     # 地区の所得の中央値（1 万ドル単位）
ave_occ = data.data[:, names.index("AveOccup")]   # 地区の人口 ÷ 世帯数
rng = np.random.default_rng(0)                     # 1 回だけ作り、以後は続きを引く

N = 100000
paths = {
    "MedInc": [np.cumsum(med_inc[rng.integers(0, len(med_inc), N)]) / np.arange(1, N + 1) for _ in range(5)],
    "AveOccup": [np.cumsum(ave_occ[rng.integers(0, len(ave_occ), N)]) / np.arange(1, N + 1) for _ in range(5)],
    "Cauchy": [np.cumsum(rng.standard_cauchy(N)) / np.arange(1, N + 1) for _ in range(5)],
}
for name, ps in paths.items():
    print(f"{name:<8} n=100 / 10000 / 100000 の平均（5 本）:",
          [tuple(round(float(p[k - 1]), 3) for k in (100, 10000, 100000)) for p in ps])
```

コーシー分布は裾が重く、期待値が定まらないので、大数の法則が置く条件を満たしません。10 万件を足しても平均は -1.1 から 1.7 に散らばり、1 件の極端な値で何度でも跳ねます。コーシー分布の形は[代表的な確率分布](../probability-distributions/)で扱っています。

近づき方には 2 つの言い方があります。[弱法則](https://www.probabilitycourse.com/chapter7/7_1_1_law_of_large_numbers.php)は、どんな小さい `ε` を決めても、`|x_bar - μ| > ε` となる確率が `n` とともに 0 に近づくと言います。強法則は、平均の列そのものが `μ` に収束する確率が 1 だと言います。どちらも、1 件増えるたびにずれが小さくなるとは言っておらず、何件で近づくかも教えてくれません。

### 標準誤差

近づく速さは、平均のばらつきで測れます。分散 `σ²` の独立な値を `n` 個平均すると、平均の分散は `σ² / n` になり、その平方根の `σ / √n` を標準誤差（standard error、SE）と呼びます。件数を 4 倍にすると標準誤差は半分に、精度を 1 桁上げるには 100 倍の件数が要ります。

この式は独立と分散が有限なことだけから出るので、正規分布への近似は要りません。導き方は[分散](../variance/)の「平均した値の分散」で説明しています。縮むのは選び方の偶然によるずれだけで、集め方の偏りは件数を増やしても残ります。

実際には `σ` は分からないので、手元の `n` 件から出した[標準偏差](../stddev/) `s` で置き換えて、`s / √n` を標準誤差とします。そこで、同じ `n` で 4000 回選び直した平均の標準偏差と、1 回の標本から出した `s / √n` が、`σ / √n` とどれだけ合うかを比べました。

```python
def draw(x, n, reps):
    """x から重複を許して n 件を選ぶ操作を reps 回行い、平均と標準偏差を返す。"""
    means, sds = [], []
    batch = max(1, 2_000_000 // n)                 # メモリに載る分ずつ選ぶ
    while len(means) < reps:
        b = min(batch, reps - len(means))
        s = x[rng.integers(0, len(x), (b, n))]
        means.extend(s.mean(axis=1))
        sds.extend(s.std(axis=1, ddof=1) if n > 1 else np.zeros(b))
    return np.array(means), np.array(sds)


ns_se = [10, 30, 100, 300, 1000, 3000, 10000]
for name, x in [("MedInc", med_inc), ("AveOccup", ave_occ)]:
    sd_of_mean, med_s = [], []
    for n in ns_se:
        m, s = draw(x, n, 4000)
        sd_of_mean.append(m.std())                 # 選び直した平均の標準偏差
        med_s.append(np.median(s) / np.sqrt(n))    # 1 回の標本から出した s/√n の中央値
    print(f"{name:<8} 平均の標準偏差 / σ/√n / 標本の s/√n（中央値）:",
          [(n, round(a, 4), round(x.std() / np.sqrt(n), 4), round(b, 4))
           for n, a, b in zip(ns_se, sd_of_mean, med_s)])
```

```text
AveOccup ... (1000, 0.3195, 0.3284, 0.0302), (3000, 0.1899, 0.1896, 0.0312), (10000, 0.105, 0.1039, 0.0788)]
```

### 正規分布に近づくのは平均

[中心極限定理](https://www.probabilitycourse.com/chapter7/7_1_2_central_limit_theorem.php)は、値が独立同分布で、分散が `0 < σ² < ∞` なら、`(x_bar - μ) / (σ / √n)` の分布が `n` を増やすと標準正規分布 `N(0, 1)` に近づくと言っています。この値は、平均と期待値のずれが標準誤差の何個分かを表します。有限の `n` では、データではなく平均の分布を `N(μ, σ² / n)` で近似する根拠になります。

どれだけ近づいたかは、選び直した平均の歪度で測れます。1 件ずつの値の歪度を `γ` とすると、独立な `n` 件を平均した値の歪度は `γ / √n` です。10000 回選び直した平均の分布を描き、歪度を数えました。

```python
rows = [("MedInc", med_inc, [1, 5, 30]), ("AveOccup", ave_occ, [30, 1000, 30000])]
for name, x, nlist in rows:
    for n in nlist:
        m, _ = draw(x, n, 10000)
        below = np.mean(m < x.mean())              # 真の平均より下に出た割合
        print(f"{name:<8} n={n:<6} 平均の歪度 {stats.skew(m):6.2f}（γ/√n = {stats.skew(x) / np.sqrt(n):6.2f}）"
              f"  真の平均より下 {below:.1%}")
```

MedInc の歪度は 1.65 で、平均の歪度は `n = 30` で 0.31 まで下がり、ヒストグラムは `N(μ, σ² / n)` の曲線に重なります。MedInc では、「`n` が 30 を超えれば」という目安が成り立ちました。

AveOccup の歪度は 97.6 です。`n = 1000` でも平均の歪度は 3.05 で、平均の 82% が真の平均より下に出ました。真の平均より下に細い山があり、そこから右へ離れた所に小さな山が並ぶ形で、正規分布とは似ていません。歪度が 0.5 前後まで下がり、曲線に重なるのは 3 万件でした。

平均の歪度を 0.5 まで下げるのに要る件数は、`γ / √n = 0.5` を解いた `(γ / 0.5)²` で見積もれます。

| 列 | データの歪度 `γ` | 平均の歪度が 0.5 になる件数 |
|---|---|---|
| MedInc | 1.65 | 11 件 |
| AveOccup | 97.6 | 約 3 万 8000 件 |

ここでの `γ` は 20640 地区全体から測った値です。手元の標本が上位の値を含まないと、標本から測った `γ` は小さく出て、要る件数も少なく見積もられます。

<details>
<summary>Q-Q プロットとベリー・エッセンの定理</summary>

データが正規分布に近いかは、Q-Q プロットで見ることがよくあります。Q-Q プロットは、データの分位点を正規分布の分位点と並べた図で、点が直線に乗れば正規分布に近いと読みます。ただ、データの Q-Q プロットが直線から外れていることだけでは、何件で平均が正規分布に近づくかは分かりません。上の `(γ / 0.5)²` のようにデータの歪度から見積もるか、選び直した平均の分布を描きます。

正規分布とのずれが、`1 / √n` に比例する上限で抑えられることは、[Berry 氏の 1941 年の論文](https://doi.org/10.1090/S0002-9947-1941-0003498-3)と、[Esseen 氏の 1942 年の論文](https://zbmath.org/?q=an:68.0277.02)が示しました。この結果はベリー・エッセンの定理と呼ばれます。この上限の係数は、期待値からのずれの絶対値を 3 乗して平均した値と、標準偏差を 3 乗した値との比で決まり、偏りの大きいデータほど大きくなります。

</details>

### 外れた区間の正体

冒頭の図は、標準誤差の節で定義した `draw` で `n` 件を選び、自由度 `n - 1` の [t 分布](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.t.html)で区間を作って数えました。`σ` の代わりに `s` を使う時に t 分布を使う理由は、[仮説検定・p 値・信頼区間](../hypothesis-test/)で説明しています。t 分布の区間がちょうど 95% を含むのは元データが正規分布に従う時で、それ以外では近似です。

```python
def coverage(x, n, reps=10000):
    """t 分布の 95% 信頼区間が、20640 行の平均（真の平均）を含んだ割合。"""
    m, s = draw(x, n, reps)
    half = stats.t.ppf(0.975, n - 1) * s / np.sqrt(n)
    return np.mean(np.abs(m - x.mean()) <= half)


ns = [10, 30, 100, 300, 1000, 3000, 10000, 30000, 100000]
for name, x in [("MedInc", med_inc), ("AveOccup", ave_occ)]:
    print(f"{name:<8}", "  ".join(f"n={n}: {coverage(x, n):.1%}" for n in ns))
```

```python
    print(f"AveOccup {ave_occ[i]:7.1f}  人口 {pop[i]:6.0f}  世帯数 {pop[i] / ave_occ[i]:4.0f}")
big = ave_occ > 20
print(f"AveOccup が 20 を超える地区: {big.sum()} 件、除いた平均 {ave_occ[~big].mean():.3f}、"
      f"除いた標準偏差 {ave_occ[~big].std():.3f}")
```

```text
AveOccup  1243.3  人口   7460  世帯数    6
AveOccup   599.7  人口   4198  世帯数    7
AveOccup   502.5  人口   6532  世帯数   13
AveOccup   230.2  人口   6675  世帯数   29
```

一番大きい地区は、世帯が 6 つしか無いのに人口が 7460 人で、1 世帯あたり 1243 人になります。AveOccup は人口を世帯数で割った値なので、分母の世帯数が人口に比べて小さい地区で大きくなります。[scikit-learn の説明](https://scikit-learn.org/stable/datasets/real_world.html#california-housing-dataset)は、部屋数と寝室数の列について、世帯が少なく空き家の多い別荘地のような地区で驚くほど大きな値を取りうると書いています。

AveOccup の 10 地区については理由の記載が無く、世帯に入らない人が多く住む地区だろうと推測できるだけです。

20 を超える地区は 20640 地区のうち 10 件だけで、除くと平均は 3.071 から 2.933 に、標準偏差は 10.4 から 0.87 に下がります。0.138 の差は、たった 10 件が作っています。

<br>

#### 10 件を選ぶかどうか

1000 件を選ぶと、10 件のどれかが入る数は平均 0.48 件です。入らない標本では、平均は 2.933 の近くに、`s` は 0.87 の近くに出るので、区間は狭く、真の平均 3.071 より下に収まります。冒頭の図とは別の乱数で 1000 件を 3000 回選び、10 件を含んだかどうかで分けて数えました。

`s / √n` で幅を決めるから外れるのなら、`s` を使わない方法では当たるのでしょうか。そこで、[ブートストラップ](https://doi.org/10.1214/aos/1176344552)の区間も 500 回分並べます。ブートストラップは、手元の 1000 件から重複を許して選び直し、平均のばらつきを見積もる方法です。ここでは、選び直した平均の 2.5% 点から 97.5% 点までを区間にするパーセンタイル法を使います。

```python
n = 1000
idx = rng.integers(0, len(ave_occ), (3000, n))        # 1000 件を 3000 回選ぶ
sample = ave_occ[idx]
m, s = sample.mean(axis=1), sample.std(axis=1, ddof=1)
half = stats.t.ppf(0.975, n - 1) * s / np.sqrt(n)
hit = np.abs(m - ave_occ.mean()) <= half
no_big = ~(sample > 20).any(axis=1)                   # 20 を超える 10 地区を 1 件も選ばなかった回
print(f"n=1000: 含んだ {hit.mean():.1%}、下に外れた {np.mean(~hit & (m < ave_occ.mean())):.1%}、"
      f"上に外れた {np.mean(~hit & (m > ave_occ.mean())):.1%}")
print(f"20 を超える地区を 1 件も選ばなかった回 {no_big.mean():.1%}、そのうち含んだ {hit[no_big].mean():.1%}")
print(f"1 件以上選んだ回のうち含んだ {hit[~no_big].mean():.1%}")

boot_hit = []
for b in range(500):
    xb = sample[b]
    bm = xb[rng.integers(0, n, (1000, n))].mean(axis=1)   # 手元の 1000 件から選び直した平均を 1000 個
    lo, hi = np.percentile(bm, [2.5, 97.5])
    boot_hit.append(lo <= ave_occ.mean() <= hi)
print(f"ブートストラップの 95% 区間が含んだ割合 {np.mean(boot_hit):.1%}（t の区間は同じ 500 回で {hit[:500].mean():.1%}）")
```

```text
n=1000: 含んだ 32.1%、下に外れた 67.9%、上に外れた 0.0%
20 を超える地区を 1 件も選ばなかった回 60.2%、そのうち含んだ 0.7%
1 件以上選んだ回のうち含んだ 79.6%
ブートストラップの 95% 区間が含んだ割合 32.2%（t の区間は同じ 500 回で 30.8%）
```

### テストデータの正解率

テストデータの正解率は、1 行ごとに正解なら 1、不正解なら 0 を付けた値の平均です。正解率 `p` の 1 行の分散は `p (1 - p)` なので、標準誤差は `√(p (1 - p) / n)` です。

scikit-learn に同梱の [digits](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_digits.html)（8 × 8 画素の手書き数字 1797 枚）を半分に分け、[ロジスティック回帰](../../ml/logistic-regression/)を半分で学習しました。残りの 899 行から `n` 行を選び直してテストデータとし、同じモデルの正解率がどれだけ揺れるかを 4000 回数えます。

```python
digits = load_digits()
X_tr, X_pool, y_tr, y_pool = train_test_split(digits.data, digits.target, test_size=0.5,
                                              random_state=0, stratify=digits.target)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=2000)).fit(X_tr, y_tr)
correct = (model.predict(X_pool) == y_pool).astype(float)   # 1 行ごとの正解（1）と不正解（0）
p = correct.mean()
print(f"手元の {len(correct)} 行での正解率 {p:.4f}")
for n in [50, 100, 200, 400, 800]:
    acc, _ = draw(correct, n, 4000)
    lo, hi = np.percentile(acc, [2.5, 97.5])
    print(f"n={n:<4} 正解率の 95% の範囲 {lo:.3f}〜{hi:.3f}  幅 {hi - lo:.3f}  "
          f"式の幅 2×1.96×√(p(1-p)/n) = {2 * 1.96 * np.sqrt(p * (1 - p) / n):.3f}")
```

```text
n=100  正解率の 95% の範囲 0.920〜1.000  幅 0.080  式の幅 2×1.96×√(p(1-p)/n) = 0.074

```

点が横の筋に並ぶのは、`n` 件の正解率が `1 / n` 刻みの値しか取らないからです。同じモデルでも、100 件のテストデータなら正解率は 92%〜100% の範囲で揺れます。式の幅は、選び直して数えた幅とほぼ一致しました。1 つのモデルでもこれだけ揺れるので、別々のテストデータで測った 2 つのモデルの正解率が 100 件で 1〜2 ポイント違うだけでは、差があるとは言えません。同じテストデータで比べる時の幅は、最後の節で扱います。

正解率が 1 に近い時は、0 と 1 の値が偏り、`n = 50` では式の上限が 1.015 と 100% を超えます。

件数の少ない時は、テストデータを 1 回で決めず、[交差検証](../../ml/cross-validation/)で分け方を変えて正解率を何回か出すと、ばらつきの目安は掴めます。ただ、分け方どうしで学習データが重なるので、こうして出したばらつきは小さめに出やすく、どのデータにも使える偏りの無い見積もり方は無いことが [Bengio 氏と Grandvalet 氏の 2004 年の論文](https://www.jmlr.org/papers/v5/grandvalet04a.html)で示されています。

`√(p (1 - p) / n)` は値が 0 か 1 の時だけの式です。平均二乗誤差のように行ごとの[損失](../../ml/loss-functions/)を平均する指標では、行ごとの損失の標準偏差 `s` から `s / √n` で幅を出せます。

### 独立でない行

ここまでの実験は、重複を許して 1 件ずつ選ぶことで、値が互いに独立になるようにしていました。時系列のように、前の値に引きずられるデータでは、この前提が崩れます。

1 つ前の値に `ρ` を掛けて新しい揺れを足す系列を作り、独立とみなして t の 95% 信頼区間を作りました。系列のどの時点も平均 0、分散 1 です。

```python
def ar1(rho, n, reps):
    """1 つ前の値に rho を掛けて新しい揺れを足す系列。どの時点も平均 0、分散 1。"""
    z = rng.normal(size=(reps, n))
    x = np.empty_like(z)
    x[:, 0] = z[:, 0]
    for t in range(1, n):
        x[:, t] = rho * x[:, t - 1] + np.sqrt(1 - rho**2) * z[:, t]
    return x


for rho in [0.0, 0.5, 0.9]:
    cv = []
    for n in [10, 30, 100, 300, 1000, 3000]:
        x = ar1(rho, n, 4000)
        half = stats.t.ppf(0.975, n - 1) * x.std(axis=1, ddof=1) / np.sqrt(n)
        cv.append(np.mean(np.abs(x.mean(axis=1)) <= half))
    limit = 2 * stats.norm.cdf(1.96 * np.sqrt((1 - rho) / (1 + rho))) - 1
    print(f"ρ={rho}: " + "  ".join(f"n={n}: {v:.1%}" for n, v in zip([10, 30, 100, 300, 1000, 3000], cv))
          + f"  （n が大きい時の値 {limit:.1%}）")
```

```text
ρ=0.0: n=10: 94.8%  n=30: 94.7%  n=100: 95.7%  n=300: 95.3%  n=1000: 95.3%  n=3000: 95.1%  （n が大きい時の値 95.0%）
ρ=0.5: n=10: 76.0%  n=30: 73.0%  n=100: 73.3%  n=300: 74.4%  n=1000: 73.6%  n=3000: 74.2%  （n が大きい時の値 74.2%）
ρ=0.9: n=10: 32.8%  n=30: 32.0%  n=100: 34.2%  n=300: 33.4%  n=1000: 34.5%  n=3000: 34.1%  （n が大きい時の値 34.7%）
```

{{< figure src="lln_dependent.webp" alt="横軸は系列の長さ n の対数（10〜3000）、縦軸は真の平均 0 を含んだ割合。青い ρ=0.0 は 95% の点線の上にある。緑の ρ=0.5 は 73〜76% で横ばい、赤の ρ=0.9 は 32〜35% で横ばいで、それぞれの点線（n が大きい時の値 74% と 35%）の上を進む" caption="直前の値と相関 ρ を持つ系列で、独立とみなして作った 95% 信頼区間" align="center" >}}

`ρ = 0.9` では、`n` を 10 から 3000 に増やしても、区間が真の平均を含む割合は 32〜35% のままでした。この系列では、平均が持つ本当の分散は `σ² / n` のおよそ `(1 + ρ) / (1 - ρ)` 倍、`ρ = 0.9` なら 19 倍になります。独立とみなした区間は、その平方根の約 4.4 倍だけ狭いままで、`n` を増やしても比は変わりません。

それでも平均の分散は `1 / n` で縮み続け、平均は 0 に近づきます。ただし、これは独立同分布を置いた大数の法則からは言えず、定常な系列に広げたエルゴード定理による結果です。崩れるのは、`s / √n` で作った区間の方です。どの値も同じ揺れを共有する場合は、これとは違い、平均の分散そのものが下げ止まります。その様子は[分散](../variance/)で扱っています。

同じことは、1 人のユーザーが何回も訪れるログで、訪問ごとの行をそのまま平均した時にも起こりえます。ユーザーごとに平均してから、ユーザーを 1 件として数えれば、行が独立に近くなります。時系列の評価で行を分ける方法は、[時系列予測](../../ml/time-series-forecasting/)で説明しています。集めている途中で分布そのものが変わる場合も、過去の平均は今の期待値に近づきません。この変化は[データドリフト](../../mlops/data-drift/)で扱っています。

### ± を付ける前に見ること

平均に ± を付ける前に、最大値と、上位の数件を除くと平均がどれだけ動くかを見ます。この動きが区間の幅より大きければ、手元の標本が上位の値を含むかどうかで区間が当たるかどうかが決まり、ブートストラップに替えても直りません。

上位の値が大きく効くなら、次に知りたいのが本当に平均なのかを考えます。AveOccup で典型的な地区の値を知りたいなら[中央値](../median/)や、`log1p` で変換した後の平均が向きます。州全体の 1 世帯あたりの人数を知りたいなら、地区ごとの値を平均せず、全人口を全世帯数で割ります。売上の合計を見積もるように平均そのものが要るなら、件数を増やすか、大きい値の地区やユーザーを別に数えます。

行の取り方も見ます。同じユーザーや連続した時刻の行が並ぶなら、ユーザーや時間の塊ごとに平均してから区間を作ります。テストデータの正解率なら、`√(p (1 - p) / n)` で 1 つのモデルの幅を出します。同じテストデータで 2 つのモデルを比べる時は、行ごとに片方の正解から他方の正解を引いた値を 1 件として平均し、その `s / √n` で差の幅を出します。

手元のデータで冒頭の図と同じものを描くなら、データ自体を母集団とみなし、`n` 件を選び直して区間を作り、全体の平均を含むかを数えます。この方法で分かるのは、手元に入っている上位の値がどう効くかまでです。ブートストラップと同じく、手元に無い極端な値の影響は見えません。
