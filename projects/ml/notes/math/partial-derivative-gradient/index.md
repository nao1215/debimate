偏微分は、変数が複数ある関数で、1 つの変数だけを少し動かし、残りを固定した時の傾きです。勾配は、全ての変数について偏微分を求めて並べたベクトルです。機械学習では、損失をモデルの重みで偏微分した勾配を求め、その逆の向きに重みを動かして学習します。

勾配を式で書いたら、合っているかを数値微分と比べて確認します。数値微分は、重みを 1 つだけ小さな幅 `h` ずらして損失の差を測り、`h` で割って傾きを近似する方法です。`h` を小さくするほど、本当の傾きに近づくと思うかもしれません。

[scikit-learn](https://scikit-learn.org/stable/) に同梱の [breast_cancer](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_breast_cancer.html)（乳腺の細胞核を写した画像から測った 30 列、569 件）で[ロジスティック回帰](../../ml/logistic-regression/)の損失を作り、30 列の重みに切片を加えた 31 個の重みについて勾配を式と数値微分で求めて、`h` を 1e-1 から 1e-16 まで変えて比べました。

{{< figure src="pdg_cover.webp" alt="横軸はずらす幅 h で、右へ行くほど 1e-1 から 1e-16 へ小さくなる。縦軸は式で求めた勾配との相対誤差の対数。黒い中心差分 float64 は h=1e-5 で最小の 1.9e-11 になった後に増え、h=1e-12 で 1.8e-4、1e-16 で約 1 になる。青い前進差分 float64 は h=3e-8 付近で最小の 1.8e-8。赤い中心差分と橙の前進差分の float32 は、それぞれ h=1e-2 と 6e-4 付近で最小になる。SciPy の既定の h である 1.49e-8 の点線の付近では、橙の誤差が 10 を超え、赤も 5〜9 になる。h=1e-8 から 2e-9 の間で誤差はさらに上がり、橙は最大 25.4、赤は最大 14.4 になる。h=1e-9 より小さい所では、どちらも誤差 1 に張り付く" caption="h を小さくすると、誤差はある所から増える（breast_cancer、31 個の重み）" align="center" >}}

前進差分は `w` と `w + h`、中心差分は `w - h` と `w + h` の 2 点の差で傾きを測ります。縦軸の相対誤差は、式の勾配とのずれを勾配の長さで割った値で、1 ならずれが勾配と同じ大きさです。

中心差分を 64 ビットの浮動小数点数（float64）で計算すると、誤差は `h = 1e-5` の 1.9e-11 が一番小さく、`h = 1e-12` では 1.8e-4 と約 1000 万倍に増えました。同じ損失を 32 ビット（float32）で計算すると、[SciPy](https://scipy.org/) の [`check_grad`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.check_grad.html) を既定値 1.49e-8 で使うと、数値微分が正しい勾配の 15 倍ずれます。どちらもエラーや警告は出ません。

これは、勾配の式を数値微分と比べる勾配確認（gradient check）で困ります。式が正しいのに数値微分と合わない、あるいは `h` を変えるたびに合ったり外れたりします。

<br>

本記事では、勾配を自分で計算して確認したい人と、勾配の式を手で書く人に向けて、次の疑問に答えます。

- 偏微分は、何を固定して何を測るのか。
- 勾配は、なぜ損失が最も大きく増える向きを指すのか。
- ロジスティック回帰の勾配は、どう式にするのか。
- 数値微分の `h` は、なぜ小さすぎると誤差が増えるのか。
- 損失が float32 だと、勾配確認はどう壊れるのか。
- `h` に悩まずに微分を求める方法はあるか。
- 列の単位を変えると、勾配の向きは変わるのか。

実験は [NumPy](https://numpy.org/) 2.5.4、scikit-learn 1.9.1、SciPy 1.18.1 で行いました。図の処理も含めた完全なコードは [partial-derivative-gradient_gen.py](https://github.com/nao1215/debimate/blob/main/projects/ml/scripts/notes/partial-derivative-gradient_gen.py) にあります。

### 1 つの重みだけを動かす偏微分

最初に、重みが 2 つだけのモデルで偏微分を見ます。breast_cancer の列のうち、平均 0・分散 1 に[標準化](../../ml/standardization/)した mean radius と mean texture の 2 列だけを使い、重みを `w1` と `w2` とします。mean radius は細胞核の半径を平均した値、mean texture は画像の濃淡のばらつきを平均した値です。

予測した確率と正解のずれを測る損失には、交差エントロピーの平均を使います。損失の形は[損失関数](../../ml/loss-functions/)で説明しています。

```python
def loss(w, X=X, y=y):
    z = X @ w
    return np.mean(np.log(1 + np.exp(z)) - y * z)    # 交差エントロピーの平均

X2 = X[:, [0, 1]]                                    # mean radius と mean texture
P = np.array([-1.0, 1.5])                            # 偏微分を調べる点
h = 1e-5
d1 = (loss(P + [h, 0], X2) - loss(P - [h, 0], X2)) / (2 * h)
d2 = (loss(P + [0, h], X2) - loss(P - [0, h], X2)) / (2 * h)
print(f"∂L/∂w1 = {d1:.4f}   ∂L/∂w2 = {d2:.4f}")
```

```text
∂L/∂w1 = 0.2657   ∂L/∂w2 = 0.3973
```

`∂L/∂w1` は、`w2` を 1.5 に固定して `w1` だけを動かした時の、損失 `L` の傾きです。`∂` は偏微分の記号で、他の変数を固定していることを表します。式で求める時は、固定した変数を定数とみなして、1 変数の微分をします。例えば `z = 3 w1 + 2 w2` を `w1` で偏微分すると、`2 w2` は定数なので消え、`∂z/∂w1 = 3` です。次の図で左は損失の等高線で、点 P を通る 2 本の点線で損失を切った断面が、中央と右のグラフです。

{{< figure src="pdg_slices.webp" alt="3 枚の図。左は w1 を横軸、w2 を縦軸にした損失の等高線で、点 P=(-1, 1.5) を通る赤い横の点線と緑の縦の点線を引いている。中央は w2=1.5 で切った断面で、損失は w1 とともに増え、P での接線の傾きは 0.266。右は w1=-1.0 で切った断面で、w2=-0.8 付近で最小になり、P での接線の傾きは 0.397" caption="損失を 1 つの重みの向きに切った断面と、その傾き" align="center" >}}

断面にすると、どちらも 1 変数の関数になり、P での接線の傾きが偏微分です。2 つの偏微分を並べた `(0.2657, 0.3973)` が、P での勾配 `∇L` です。

### 勾配の向きと大きさ

勾配は軸に沿った傾きを 2 つ並べただけですが、軸から外れた向きの傾きも決めます。長さ 1 の向き `u` に動かした時の傾きは、`∇L・u`（勾配と `u` の内積）で求まります。内積は 2 つのベクトルの成分ごとの積の和で、[ベクトルと行列の演算](../vector-matrix-ops/)で説明しています。

P から 1 度刻みで 360 通りの向きに `h` だけ動かし、損失の差から傾きを測りました。

```python
ang = np.radians(np.arange(0, 360, 1.0))
slopes = []
for a in ang:
    u = np.array([np.cos(a), np.sin(a)])             # 長さ 1 の向き
    slopes.append((loss(P + h * u, X2) - loss(P - h * u, X2)) / (2 * h))
```

```text
傾きが最大の向き 56 度、その傾き 0.4780
勾配の向き 56.2 度、勾配の長さ 0.4780
0 度の傾き 0.2657、90 度の傾き 0.3973
```

{{< figure src="pdg_direction.webp" alt="左は損失の等高線に、点 P から右上へ伸びる赤い勾配の矢印と、左下へ伸びる青い勾配の逆の矢印を描いた図で、矢印は等高線と直交する。右は横軸が動かす向き 0〜360 度、縦軸がその向きの傾きのグラフで、曲線は 56 度で最大 0.478、236 度付近で最小 -0.478 になる。0 度の点は 0.266 で ∂L/∂w1、90 度の点は 0.397 で ∂L/∂w2" caption="P から動かす向きと、その向きで測った損失の傾き" align="center" >}}

傾きは 56 度で最大の 0.478 になり、勾配の向き（56.2 度）と長さ（0.478）に一致しました。勾配と `u` の角度を `θ` とすると、傾きは `|∇L| cos θ` なので、`u` が勾配と同じ向きの時に最大になります。0 度と 90 度の傾きは、前の節で求めた 2 つの偏微分そのものです。

傾きが 0 になる 146 度と 326 度は、等高線に沿う向きです。勾配はこの向きと直交するので、左の図で矢印は等高線を垂直に横切ります。損失を一番速く減らす向きは、勾配と逆の 236 度です。[最急降下法](../gradient-descent-sgd/)は、学習率 `η` という小さな数を勾配に掛けて `w ← w - η ∇L` と重みを更新し、この向きに少しずつ進みます。

勾配が 0 になる点では、どの向きの傾きも 0 です。[線形回帰](../../ml/linear-regression/)の正規方程式は、損失の勾配を 0 と置いて解いたものです。二乗誤差の和 `|Xw - y|²` を展開すると `w^T (X^T X) w - 2 y^T X w + y^T y` で、最初の項は `w^T A w` の形をした 2 次形式です。2 次形式の勾配は `(A + A^T) w` で、`X^T X` のような[対称行列](../eigen-decomposition/)なら `2 A w` になります。そのため勾配は `2 X^T X w - 2 X^T y` で、これを 0 と置くと正規方程式 `X^T X w = X^T y` が出ます。ただし、勾配が 0 の点が最小とは限らず、[凸でない関数](../convex-functions/)では極大や鞍点のこともあります。

### ロジスティック回帰の勾配を式で求める

ここからは、30 列と切片の 31 個の重みを全て使います。重みが増えても、勾配は 31 個の偏微分を並べたベクトルです。ただし、31 個を 1 つずつ数値微分で求めると、損失を 62 回計算します。学習では毎回勾配を使うので、式で求めます。

損失は、重みから `z = Xw` を作り、`z` から損失を作る 2 段の関数です。このような関数の微分は、各段で微分した値の掛け算になり、これを連鎖律（chain rule）と呼びます。

```mermaid
flowchart LR
    W["重み w_j"] -- "∂z_i/∂w_j = x_ij" --> Z["z_i = 行 i の x と w の内積"]
    Z -- "∂L_i/∂z_i = p_i - y_i" --> L["行 i の損失 L_i"]
```

`L_i = log(1 + e^z_i) - y_i z_i` を `z_i` で微分すると `e^z_i / (1 + e^z_i) - y_i` です。前半の `e^z_i / (1 + e^z_i)` は `z_i` をシグモイド関数に通した値で、ロジスティック回帰が予測した確率 `p_i` そのものです。`z_i` の中で `w_j` 以外の重みが掛かる項は定数として消えるので、`∂z_i/∂w_j = x_ij` です。これを掛け、569 行で平均すると、`∂L/∂w_j = mean_i((p_i - y_i) x_ij)` になります。行列で書くと `X^T (p - y) / n` です。

```python
def grad(w, X=X, y=y):
    p = 1 / (1 + np.exp(-(X @ w)))                   # 予測した確率
    return X.T @ (p - y) / len(y)
```

予測が正解より大きい行ほど `p_i - y_i` が大きく、その行で値の大きい列の重みほど偏微分が大きくなります。勾配の逆に進むと、その重みが大きく減ります。層を何段も重ねたニューラルネットワークでも、損失から 1 段ずつ連鎖律を当てはめて勾配を求めます。これが[誤差逆伝播法](../../ml/backpropagation/)です。層が深いと連鎖律の掛け算で勾配が極端に小さくなることがあり、[活性化関数](../../ml/activation-functions/)の選び方はこれに関わります。

重みの代わりに入力で偏微分すると、どの入力を動かすと予測が大きく変わるかが分かります。画像の分類で入力の画素についての勾配を描く [Saliency Map](https://arxiv.org/abs/1312.6034) はこの使い方で、[特徴量の重要度](../../ml/feature-importance/)を測る考え方の 1 つです。

### 数値微分の h と誤差

式の `grad` が合っているかは、数値微分と比べれば分かります。冒頭で触れた前進差分は `(L(w + h) - L(w)) / h`、中心差分は `(L(w + h) - L(w - h)) / 2h` です。31 個の重みを[標準偏差](../stddev/) 0.1 の乱数で決め、冒頭の図を作ったコードから、誤差を求める部分を抜粋します。

```python
rng = np.random.default_rng(0)
w0 = rng.normal(scale=0.1, size=X.shape[1])          # 31 個の重み
g = grad(w0)

def numeric_grad(f, w, h, kind="central"):
    out = np.zeros(len(w))
    for i in range(len(w)):
        e = np.zeros_like(w)
        e[i] = h
        if kind == "forward":
            out[i] = (f(w + e) - f(w)) / h
        else:
            out[i] = (f(w + e) - f(w - e)) / (2 * h)
    return out

def rel_err(a):
    return np.linalg.norm(a - g) / np.linalg.norm(g)

hs = 10.0 ** -np.arange(1, 16.01, 0.25)
errs = [rel_err(numeric_grad(loss, w0, hh)) for hh in hs]
```

`rel_err` が冒頭で定義した相対誤差です。1 に近づくと、ずれが勾配と同じ大きさになり、比べる意味がありません。

```text
中心差分 float64: 一番小さい誤差 1.9e-11（h=1e-05）
  h=1e-02:1.1e-05  h=1e-03:1.1e-07  h=1e-05:1.9e-11  h=1e-07:1.6e-09  h=1e-12:1.8e-04
前進差分 float64: 一番小さい誤差 1.8e-08（h=3e-08）
```

#### 打ち切りの誤差と丸めの誤差

誤差が `h` の途中で底を打つのは、誤差の源が 2 つあるからです。1 つは、曲線を 2 点を結ぶ直線で近似したことによる打ち切りの誤差で、`h` が大きいほど増えます。もう 1 つは、損失を float64 で計算した時に出る丸めの誤差で、`h` が小さいほど増えます。

2 つを分けるために、Python 標準の [`decimal`](https://docs.python.org/3/library/decimal.html) で損失を 60 桁の精度で計算し直しました。60 桁で求めた差分と式の差が打ち切りの誤差、float64 と 60 桁で求めた差分の開きが丸めの誤差です。対象は mean radius の重み 1 つです。次のコードは 1 つの `hh` での抜粋で、`loss_dec` と `true_k` の定義は[完全なコード](https://github.com/nao1215/debimate/blob/main/projects/ml/scripts/notes/partial-derivative-gradient_gen.py)にあります。

```python
# loss_dec(k, dh): k 番目の重みだけ dh ずらした損失を 60 桁で計算する関数
# true_k: 前の節の式 mean_i((p_i - y_i) x_ij) を 60 桁で計算した偏微分
getcontext().prec = 60
k = 0                                                # mean radius の重みの番号
e = np.zeros_like(w0)
e[k] = hh                                            # k 番目の重みだけ hh ずらす
dh = Decimal(float(hh))
num64 = (loss(w0 + e) - loss(w0 - e)) / (2 * hh)                # float64 の中心差分
num_exact = (loss_dec(k, dh) - loss_dec(k, -dh)) / (2 * dh)      # 丸めの無い中心差分
trunc = abs(num_exact - true_k) / abs(true_k)                    # 打ち切りの誤差
rnd = abs(Decimal(num64) - num_exact) / abs(true_k)              # 丸めの誤差
```

{{< figure src="pdg_tradeoff.webp" alt="横軸はずらす幅 h で右へ行くほど小さい。青い点線の打ち切りの誤差は h=1e-1 の 1.5e-4 から h が 10 分の 1 になるごとに 100 分の 1 に減る。赤い点線の丸めの誤差は h が小さくなるほど増え、h=1e-12 で 8.9e-5、1e-15 で 0.29。黒い全体の誤差は 2 本の大きい方をなぞり、h=1e-5 で最小の 1.3e-12 になる" caption="mean radius の重みで偏微分した誤差の内訳（打ち切りと丸め）" align="center" >}}

中心差分の打ち切りの誤差は `h²` に比例し、`h` を 10 分の 1 にするたびに 100 分の 1 になります。丸めの誤差は逆に増え、2 本が交わる `h = 1e-5` 付近で全体の誤差が最小になりました。

丸めの誤差が増える理由は、損失の値を並べると分かります。

```text
L(w)         = 0.6891529234732848
L(w + 1e-12) = 0.6891529234736281
L(w - 1e-12) = 0.6891529234729417
```

float64 の有効桁は 16 桁ほどで、1 の次に表せる数は 1 + 約 2.2e-16 です。本記事では、この 2.2e-16 を float64 の刻みと呼びます。`h = 1e-12` では 2 つの損失が上から 12 桁まで同じで、差に残る有効桁は 4 桁ほどしかありません。その差を 2e-12 で割るので、最後の桁で起きた丸めが、そのまま 1e-4 ほどの誤差になります。

一般に、前進差分の誤差は `h` が float64 の刻みに平方根を取った値（約 1.5e-8）に近い所、中心差分は 3 乗根（約 6e-6）に近い所で最小になります。冒頭の図で最小になった位置、3e-8 と 1e-5 はこれに合います。ただし、これは損失の値や曲がり方が 1 前後である時の目安で、重みや損失の桁が違えば最適な `h` も動きます。

### float32 の損失と SciPy の check_grad

SciPy の `check_grad` は、勾配の関数と損失の関数を受け取り、前進差分と比べた差の長さを返します。既定の幅 `epsilon` は 1.49e-8 で、float64 の刻みに平方根を取った値です。同じ損失を float32 の配列で計算して渡しました。

```python
X32, y32 = X.astype(np.float32), y.astype(np.float32)   # 列と正解を float32 にする
f64 = lambda w: loss(w)
f32 = lambda w: float(loss(w.astype(np.float32), X32, y32))
print("float64 の損失:", check_grad(f64, grad, w0))
print("float32 の損失:", check_grad(f32, grad, w0))
a32 = approx_fprime(w0, f32)                         # check_grad が内部で使う前進差分
print("数値微分の値の種類:", sorted(set(a32.round(6).tolist())))
```

```text
float64 の損失: 2.106692827377226e-08
float32 の損失: 20.106216081638728
数値微分の値の種類: [0.0, 4.0]
```

勾配の長さは 1.31 なので、float32 の損失では差の長さが勾配の 15 倍になりました。数値微分の 31 個の値は、0 か 4 のどちらかでした。

{{< figure src="pdg_float32.webp" alt="2 枚の散布図。横軸は式で求めた勾配の 31 個の成分で、-0.15 から 0.36 の範囲。縦軸は float32 の損失から求めた数値微分。左の既定の epsilon 1.49e-8 では、点が縦軸の 4 の高さに 28 個、0 の高さに 3 個並び、相対誤差は 15。右の epsilon 1e-3 では、点が全て対角線の上に並び、相対誤差は 6.2e-4" caption="float32 の損失から求めた数値微分と、式の勾配（左右で縦軸の範囲が違う）" align="center" >}}

図の点線は、数値微分が式の勾配と一致する所で、正しければ点はこの線に乗ります。左は縦軸が -8〜8 なので、点線はほぼ水平に見えます。

損失 0.689 の近くで float32 が表せる数の間隔は 5.96e-8 です。損失の差は 0 か 5.96e-8 のどちらかに丸められ、1.49e-8 で割ると 0 か 4 になります。式で求めた勾配の成分は -0.15〜0.36 なので、0 か 4 の数値微分は勾配と関係の無い値です。

`epsilon` を 1e-3 にすると、相対誤差は 6.2e-4 まで下がりました。冒頭の図で float32 の 2 本は、前進差分で 6e-4、中心差分で 1e-2 付近が最小で、float64 の最適な幅とは 3 桁以上違います。

<br>

#### PyTorch の gradcheck も既定は float64 向け

[PyTorch](https://pytorch.org/) の [`torch.autograd.gradcheck`](https://docs.pytorch.org/docs/stable/generated/torch.autograd.gradcheck.gradcheck.html) は、既定で `eps=1e-6` の中心差分を使い、許容誤差 `atol=1e-5`・`rtol=1e-3` で比べます。文書には「小さな有限差分」とだけあり、中心差分であることは[実装の gradcheck.py](https://github.com/pytorch/pytorch/blob/main/torch/autograd/gradcheck.py) に書かれています。比べ方は成分ごとで、式の値と数値微分の値のずれが `atol + rtol × |数値微分の値|` 以下なら通ります。文書（2.15）には、既定の値は倍精度の入力を想定していて、FloatTensor のような低い精度では失敗しやすいと書かれています。

本記事で NumPy を使った実験で、float32 の中心差分を `h = 1e-6` で求め、この判定に当てると、31 個の成分が全て許容を超え、一番大きい所では許容の 309 倍ずれました。PyTorch 自体では測っていませんが、正しい勾配でも勾配確認が通らない可能性が高いと考えられます。モデルを float32 で学習していても、勾配確認をする時だけ損失を float64 で計算し直します。

### 複素数ステップと自動微分

`h` を小さくできないのは、近い 2 つの損失を引き算して有効桁を失うからです。複素数ステップ（complex-step）は、引き算をせずに微分を求めます。重みを虚部の向きにだけ `h` ずらし、`Im(L(w + ih)) / h` を微分とします。

この方法は、[Lyness 氏と Moler 氏の 1967 年の研究](https://doi.org/10.1137/0704019)が元になり、Squire 氏と Trapp 氏の [1998 年の論文](https://doi.org/10.1137/S003614459631241X)で数値微分の方法として示されました。

なぜ引き算が要らないかは、テイラー展開で分かります。テイラー展開は、`w` の近くで関数が取る値を `w` での値・傾き `L'`・曲がり方 `L''` などに `h` の累乗を掛けた項の和で表す式です。ずらす幅を虚数の `ih` にすると、`i² = -1` なので項が実部と虚部に分かれます。

```text
L(w + ih) =   L(w) - h²/2 · L''(w) + …               ← 実部
            + i ( h · L'(w) - h³/6 · L'''(w) + … )   ← 虚部
```

虚部を `h` で割ると、傾き `L'(w)` に `h²` に比例する誤差が付いた値になります。損失同士を引き算しないので、`h` を小さくしても丸めの誤差が増えません。導出は Higham 氏の[解説](https://nhigham.com/2020/10/06/what-is-the-complex-step-approximation/)が読みやすいです。

```python
def complex_step_grad(f, w, h):
    out = np.zeros(len(w))
    for i in range(len(w)):
        e = np.zeros(len(w), dtype=complex)
        e[i] = 1j * h                                # 虚部の向きにだけ h ずらす
        out[i] = f(w + e).imag / h
    return out
```

```text
h=1e-05  複素数ステップ 1.1e-11  中心差分 1.9e-11
h=1e-08  複素数ステップ 3.2e-16  中心差分 1.7e-08
h=1e-12  複素数ステップ 3.0e-16  中心差分 1.8e-04
h=1e-20  複素数ステップ 3.7e-16  中心差分 1.0e+00
h=1e-200 の複素数ステップ 4.0e-16
```

{{< figure src="pdg_complex.webp" alt="横軸はずらす幅 h で、1e-1 から 1e-40 まで右へ小さくなる。黒い中心差分 float64 は h=1e-5 で最小の約 2e-11 になった後に増え、1e-16 より小さい h では誤差 1 に張り付く。緑の複素数ステップ float64 は h=1e-5 まで中心差分と重なり、その後も減り続けて h=1e-8 付近から 3e-16 前後の平らな線になり、1e-40 まで変わらない" caption="中心差分と複素数ステップの誤差（31 個の重み）" align="center" >}}

複素数ステップは `h = 1e-8` から誤差が 3e-16 前後になり、`h = 1e-200` でも変わりませんでした。float64 の刻みと同じくらいの誤差なので、`h` を十分小さくしておけば悩む必要がありません。

ただし、損失の計算が全て複素数を通す必要があります。`np.logaddexp` に複素数を渡すと TypeError になり、`np.abs(-0.2 + 1e-20j)` は 0.2 を返して虚部が消えます。本記事の損失は `np.log(1 + np.exp(z))` で書いたので通りましたが、桁あふれを避けるための `abs` や `maximum` を含む損失では、黙って違う値になることがあります。

<br>

#### 4 つの方法の比べ方

4 つ目の方法として、自動微分があります。自動微分は、損失を計算するプログラムの足し算・掛け算・`exp` などの各演算に微分の規則を当てはめ、連鎖律で勾配を機械的に組み立てる方法で、[誤差逆伝播法](../../ml/backpropagation/)はその一種です。差分で近似しないので、打ち切りの誤差がありません。重みの数を `P` とした時の、4 つの方法の違いは次のとおりです。

| 方法 | 損失の計算回数 | この実験の一番小さい誤差 | 使える条件 |
|---|---|---|---|
| 前進差分 | `P + 1` 回 | 1.8e-8（`h = 3e-8`） | 損失を計算できれば使える |
| 中心差分 | `2P` 回 | 1.9e-11（`h = 1e-5`） | 損失を計算できれば使える |
| 複素数ステップ | `P` 回（複素数） | 3e-16 前後（`h ≤ 1e-8`） | 損失の計算が全て複素数を通す |
| 自動微分 | 損失を 1 回計算する数倍 | 測っていない（打ち切りの誤差は無い） | 自動微分のライブラリで損失を書く |

学習に使う勾配は、式か自動微分で求めます。数値微分は、その式や自動微分の結果を確認するために使い、重みの数が多ければ一部の重みだけを比べます。

ただし、尖った点ではどの方法でも比べるのに向きません。ニューラルネットワークでよく使う活性化関数の ReLU は、入力が負なら 0、正ならそのまま返す関数で、`x = 0` で折れ曲がっています。この点では左右で傾きが違い、自動微分のライブラリはどちらかの値を選んで返すので、数値微分と合わないのが普通です。PyTorch の `gradcheck` を説明した文書にも、微分できない点では失敗しうると書かれています。

### 列の単位と勾配の向き

最後に、勾配の向きそのものが、列の単位で変わることを見ます。最初の 2 つの重みのモデルで、mean radius の列だけを 10 倍しました。標準化した列なので単位はありませんが、半径の単位を変えたのと同じ形です。重み `w1` を 10 分の 1 にすれば、予測も損失も元のモデルと同じです。

```python
c = 10.0                                             # mean radius の列を 10 倍する
D = np.diag([c, 1.0])
Pc = P / [c, 1.0]                                    # 同じモデルを表す重み
g_scaled = grad(Pc, X2 @ D)                          # 10 倍した列での勾配
step_back = D @ g_scaled                             # 1 歩を元の列の重みに戻す
```

```text
元の列の勾配 [0.2657 0.3973]
10 倍した列の勾配 [2.6567 0.3973]
元の列の重みに戻した 1 歩の向きと、元の勾配の向きの角度 55.4 度
損失は同じか: True
```

列を 10 倍すると、その列に掛かる重みの偏微分も 10 倍になります。そのため 10 倍した列で勾配の逆に 1 歩進むと、新しい重みの動きは `w1` の向きだけ 10 倍です。新しい重みは元の `w1` を 10 分の 1 にした値に当たるので、元の重みに戻すと動きはもう一度 10 倍され、`w1` の向きに動く量は元の 100 倍になります。`w2` の向きは変わりません。

{{< figure src="pdg_units.webp" alt="損失の等高線に、点 P から 2 本の矢印を描いた図。青い元の列での勾配の逆は左下を向き、等高線と直交する。赤い mean radius を 10 倍した列での勾配の逆を元の重みに戻した矢印は、ほぼ真左を向く。2 本の角度は 55 度" caption="列の単位を変えた時に、勾配と逆の向きが回る様子（同じ点、同じ損失）" align="center" >}}

同じ点、同じ損失なのに、損失が最も大きく減る向きが 55 度回りました。損失が最小になる点は左下にある楕円の中心にあり、どちらの矢印もそこを真っ直ぐには指していません。勾配の逆が「最も大きく減る向き」なのは、重みの軸に目盛りを決めた上での話で、目盛りは列の単位で決まります。列の単位が収束までの回数をどう変えるかは、[最急降下法・SGD](../gradient-descent-sgd/) の「列の単位と収束までの回数」で、標準化との関係と一緒に測っています。

### 勾配確認をする時

勾配の式を書いたら、損失を float64 で計算し、中心差分と比べます。冒頭の図で黒い線が示すように、`h` は 1e-5 前後から始め、1e-4 と 1e-6 でも相対誤差を出します。正しい式なら、3 つとも 1e-8 より小さく、`h` を変えても大きくは動きません。どの `h` でも 1e-2 より大きければ、式の方を疑います。

モデルを float32 で学習している時も、勾配確認だけは float64 で行います。SciPy の `check_grad` や PyTorch の `gradcheck` が既定で使う幅は float64 を前提にしています。float32 の損失では、正しい勾配でも `check_grad` の誤差は冒頭の図で橙の線が示すように 1 を超え、`gradcheck` と同じ `h = 1e-6` の中心差分でも、31 個の成分が全て許容誤差を超えます。`h` を小さくして合わせようとすると、かえって誤差が増えます。

損失の計算が全て複素数を通せるなら、複素数ステップで `h = 1e-20` ほどにすれば、`h` を選ばずに float64 の精度で比べられます。`abs` や `maximum` を含む損失では使えないので、その時は中心差分に戻ります。

最後に、式が合っていても、勾配の向きは列の単位で変わります。勾配の逆に進む学習では、列の単位をそろえてから学習率を決めます。冒頭の図で黒い線が `h = 1e-5` の底から右へ上がっていく形を覚えておけば、数値微分と合わない時に、式と `h` のどちらを疑うかを決められます。
