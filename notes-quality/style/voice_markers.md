# 私が言わない言い回し（実測に基づく禁止と置換）

このファイルは、`content/notes/` のノート 47 本（約 27 万字）と、本人が書いた文章（`content/post/ja` 221 本 + `content/weekly`、約 62 万字）を突き合わせて、**ノートにだけ増えた言い回し**を並べた物である。2026-08-18 にユーザーから「スキルを直す度に自分の文体から離れていく。omokage の補正では直せない」という指摘を受けて作った。

執筆前に必ず読む。`writing_style.md` は規則が 27 節あって全部は頭に残らないが、ここは 2 つの表だけである。

## なぜ omokage では直らないのか

omokage は文字 N-gram・機能語・文字種比率の分布を見る。ここに並ぶのは「本人も使う語の、使いすぎ」と「本人が別の語で書く所での言い換え」なので、分布としては本人の記事に似たまま残る。85〜90% を保ったまま、読んだ本人が「これは自分の言い方ではない」と感じる状態が作れてしまう。頻度だけでなく、語と動詞の組み合わせ、主語、段落の接続を本人の実文と比較する。

## 何が起きていたか

ノートを書く度にスキルへ規則を足していった結果、ノート側だけで通じる言い回しが育っていた。実測（ノート作成日ごと、地の文 1,000 字あたりの下表の語の合計）:

| 日付 | 千字あたり | 備考 |
|---|---|---|
| 2026-08-05 | 28.9 | ノート 2 本目まで |
| 2026-08-08 | 49.3 | |
| 2026-08-12 | 56.1 | |
| 2026-08-14 | 59.4 | |
| 本人の技術記事 | 4.1 | `content/post/ja` 全体 |
| 本人の weekly | 5.0 | |

10 日で約 2 倍になり、本人の実測の 10 倍以上まで離れた。逆向きに、本人が普段使う接続詞・文末（下の表 2）は本人の 1/4 まで減っていた。

原因は 3 つある。

1. スキルとガイドの地の文が、この言い回しで書かれている。執筆エージェントはガイドを読んでから書くので、規則ではなく**ガイドの文体**を写す
2. 「〜と言えます」「〜する形です」を禁じた結果、逃げ場として短い自動詞（要る・決まる・残る・効く）へ寄った
3. 禁止の代わりに置いた言い換え（「ここでは」「〜と考える方がいるかもしれません」）が、ノート全体で定型化した

対策として、ガイドの地の文は手本にしない。文体の手本は `voice_samples.md` に置いた本人の実文だけである。

一方、下の 4 つは密度の話で、`[INFO] 文体距離` にしか出ない。ノートは定義と規則を書く分だけ、否定・「〜になります」・「〜で決まります」が本人のブログより増える。差の一部は文体ではなく題材なので、密度を下げるために文を壊すと本末転倒になる。直せる所だけ直す。

| 密度で見る物 | ノート / 本人（千字あたり） |
|---|---|
| 否定の文末「〜ません。」 | 2.3 / 0.9 |
| 「〜になります」 | 1.0 / 0.2 |
| 「〜ではありません」 | 0.4 / 0.1 |
| 短い自動詞の文末（決まる・残る・効く・済む・限る） | 1.1 / 0.05 |
| 強調構文「〜のは、〜からです」 | 8.8 / 1.8 |

「ここでは〜を扱いません」は本人が修正例で示した範囲の宣言なので、この数には入れない（2026-08-06 Quorum の指摘）。

## 表 3: 語の結びつきを本人の実文で確かめる

表 1・表 2 は語の頻度の話で、これは語と語の**組み合わせ**の話である。2026-08-19 に本人から「主語の選び方や文章の接続で違和感がある」という指摘を受けた時、直された表現は全てこの型だった。

| 直された表現 | 本人の用例数 | 何が起きていたか |
|---|---|---|
| どちらも壊れ方を**持って**います | 0 | 壊れ方は所有する物ではない |
| 成立した課金を**取りこぼ**します | 0（別の意味で 1） | 課金は落とす物ではない。食い違うのは記録である |
| **効果が積み上が**ります | 0 | 残高が減る、で足りる所を抽象語にした |
| 操作を代入**に書き直せ**ない | 0 | 代入は書き直す先の形式ではない |
| 同じトランザクションで**同じ DB に**書き | — | 「同じ」が 2 回続き、指す先も別 |

いずれも文法的に正しく、`style_check.sh` も omokage も通る。頻度の表にも載らない。判定できるのは、本人が同じ組み合わせを書いているかどうかだけである。

```bash
bash ~/.claude/skills/create-tech-notes/scripts/author_grep.sh "壊れ方を持" "効果が積み上が"
```

本人の記事（`content/post/ja` + `content/weekly`、約 54 万字）とノートの両方を数え、本人が 0 件でノートにあるものを「ノート専用」として出す。0 件が必ず誤りという事ではない。題材が違えば語も違う。次にやるのは、同じ意味を本人がどう書いているかを検索して探す事である。

当てるのは、抽象名詞と動詞を組み合わせた所である。具体的な物（残高・行・接続）が主語や目的語なら、まず外さない。

## 表 4: 定型化した宣言文（2026-08-19 実測）

同じ型の文が全ノートに並ぶと、リファレンスではなくテンプレートの束に見える。本人から「毎回同じものを書くのは変だ」という指摘を受けた。

| 型 | ノート 49 本中 | 本人 54 万字中 |
|---|---|---|
| `〜を扱い、` | 22 本 | **0 件** |
| `対象外とします` | 13 本 | 1 件（apt の更新対象、別の意味） |
| `本ノートでは` | 20 本 | —（本人は「本記事では」） |

本人の範囲宣言は、扱う事だけを 1 節で書き、動詞を場面で変える形である。

- 本記事では、電源投入から init プロセスが立ち上がるまでを記載します。
- 本記事では、この差異を説明します。
- 本記事では、ヒアドキュメントの書き方を比較します。
- 本記事では全文を示しません。

除外を並べた後半（「〜は対象外とします」）は本人の型に無い。範囲宣言そのものを毎回置く必要も無い。題名が扱う範囲を超えている時だけ、扱う側を 1 文で書く（→ `writing_style.md` §14 型1）。

## 表 6: 主語に何を選んでいるか（2026-08-19 実測）

「は」の直前に来る語の上位が、本人とノートで別物になっていた。

| | 上位に来る語 |
|---|---|
| 本人 | 本記事で / 具体的に / 今回 / まず（副詞的な枠付け）と、説明している対象そのもの |
| ノート | 以下 / のドキュメント / 公式ドキュメント / 論文 / ここで / 本ノートで |

ノートは、**文書と出典が主語になっている**。`writing_style.md` §25 は人名と識別子を主語から外す規則だが、外した先が「ドキュメント」「論文」へ移っただけだった。出典を主語にした形は 1 万字あたり 本人 0.13 / ノート 2.43 で、19 倍の差がある。

「以下が〜です」は別で、本人も図表の導入に使う（→ 表 2）。主語から外すのは出典の方である。

主語に置くのは、その節が説明している対象である。出典は文末かリンクで示し、「以下」「ここ」は主語ではなく副詞として使う。

- 悪い: 「公式ドキュメントは、〜と説明しています」「以下が、〜の一例です」が節ごとに並ぶ
- 良い: 「行ロックは、トランザクションが終わるまで保持されます」（対象が主語）

## ユーザー指摘で入った形は残す

下の 2 つは、本人が修正例として書いた形である（`writing_style.md` §13）。禁止しない。ただしノート全体で定型化しているので、回数だけ制限する。

| 形 | 出どころ | 上限 |
|---|---|---|
| 〜と考える方がいるかもしれません | 2026-08-05 Heartbeat の指摘（読者を主語にする） | 1 本に 1 回 |
| ここでは、〜を扱い、〜は対象外とします | 2026-08-06 Quorum の指摘（範囲の宣言） | 1 本に 1 回 |

接続の「が」と書き出しの「また、」は、2026-08-19 更新の `writing_style.md` §16 で禁止を解除している。本人の用例と文脈に合わせて使い、一律に削除しない（2026-11-03、文体再点検で旧指示の不整合を解消）。

## 数え方

```bash
bash ~/.claude/skills/create-tech-notes/scripts/style_check.sh <記事の .md パス>
```

`[NG] 本人が使わない言い回し` と `[INFO] 文体距離` に、上の表の語の回数と密度が出る。NG は全部潰す。INFO は、本文を壊さずに直せる所だけ直す。

新しい言い回しがノート側で育っていないかを見るには、次で数え直す。ノートだけに偏っている語が見つかったら、この表へ足す。

```bash
cd ~/ghq/github.com/nao1215/debimate
grep -oh '<語>' content/notes/*/*/index.md | wc -l
grep -oh '<語>' content/post/ja/*/index.md content/weekly/*/index.md | wc -l
```

## 2026-08-18 に既存 47 本へ当てた補正

上の表を作った日に、既存ノート 47 本を「内容は変えず表現だけ」直した。方言の密度は千字あたり 50.1 から 25.9 へ下がり（本人 4.2）、`[NG] 本人が使わない言い回し` は 0 になった。omokage のスコアは 89〜90% のまま動かず、この差が omokage では見えない事が実測で確かめられた。

直した物と、直さなかった物は次の通り。同じ判断を後の補正でも使う。

| 直した | 残した |
|---|---|
| 上図 → 上記の図（214 件）、要る → 必要（131 件）、〜にあたります（27 件）、助詞「へ」→「に」（約 900 件）、〜ためです → からです、よい → 良い | 「〜のは、〜からです」、「〜ではありません」、「〜になります」、「決まります」「扱います」の密度 |
| 出典を主語にした「〜と書いています」→ 資料を場所にした「〜には〜と書かれています」（145 件） | 人の判断が主張の一部になっている「Fowler 氏は〜と説明しています」 |
| 「〜を以下に示します」を 1 本 1 回に減らし、「以下の通りです」「以下が〜です」へ（194 件） | 1 本に 1 回残した分（本人も使う） |
| 「〜そのもの」のうち、外しても意味の変わらない物 | 「X そのものではなく Y」の対比 |
| 前を正面から否定している「ただし、」→「しかし、」（6 件） | 留保・例外を足す「ただし、」 |

残した側は、文体ではなく題材から来ている分が混ざっている。ノートは定義と規則を書くので、否定と「〜で決まります」は本人のブログより増える。密度を下げるために文を壊すと、omokage のスコアのために文章を壊すのと同じ事になる。
