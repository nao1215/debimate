## 面白さ（4 因子、各 0〜3。掛け算で 0〜81）
著者の整理: 面白さ = 意外性 × 具体性 × 独自性 × 読者との関連性。どれか 1 つが 0 なら面白さは 0。
- 意外性: 直感に反する挙動・結果が、冒頭か、その話が主題の節で示されるか（欠点の補足などにしか無ければ 1。その場合、テンプレ感では二重に引かない）。3 は冒頭（「本記事では」の段落より前）に実験か事故の結果（概念図ではない。ただし後の実験の結果をそのまま描いた図は可）がある時だけ。0 = 無い（定義と構成の説明だけ）、1 = 本文の途中に少し、2 = 節の主題になっている、3 = 冒頭のフックになっていて実験か事故で示される
- 具体性: 実験・実測・実画面・実在の事故・具体的な数値があるか（実在の事故の報告 > 実在のシステムの利用例、実測 > 計算・シミュレーション の順に重く見る）。0 = 抽象的な説明だけ、1 = 架空の例、2 = 手元の実験か実在の事例が 1 つ、3 = 実験と実在の事例の両方、数値で示す
- 独自性: 他の解説記事に無い視点・実験・組み合わせ・著者の経験があるか。0 = 教科書と同じ、1 = 図か例の作りに工夫、2 = 独自の実験か比較、3 = 著者の経験や、他に無い結論。経験を無理に求めない（weeknotes 由来のノートで補う方針）
- 関連性: 読者（Web・DB の経験があるエンジニア）が自分の仕事の場面と結び付けられるか。0 = 結び付かない、1 = 一般論、2 = 困る場面が書かれている、3 = 冒頭で困る場面を示し、判断の材料を渡す

## その他の軸（各 1〜5）
- 理解しやすさ: 節の並びが大きい話から小さい話へ進み、前の節を受けているか。語を使う前に定義しているか（抜き出しで見える範囲で）
- フック: 冒頭の 3 段落で、読み進めたくなる問い・結果・場面があるか。引用して示す
- 持ち帰り: 読後に使える判断・数字・やり方を、具体的に箇条書きで挙げられるか。条件付きの判断・数値・手順だけを数え、利点・欠点の一般論は数えない。挙げられた数で付ける（0〜1 個 = 1、2 個 = 2、3 個 = 3、4 個 = 4、5 個以上で判断の基準を含む = 5）
- 回遊（参考。総合には使わない）: 他のノートへのリンク（out_links）と、他のノートから張られたリンク（inbound）の数、次に読むノートへの導線。2026-11-12 著者「回遊基準が厳しい。回遊はあるといいなぐらいのレベル。むしろ相互リンクできてないほうが気になる」。リンクの数は点にしない。張るべき所（本文で別のノートの題材を説明なしに使っている所）にリンクが無い「相互リンクの抜け」は、関門（notes-quality/crosslinks.py）が見る
- 実験の見せ方: 実験が無い = なし、実験はあるが図が無い = 1、図はあるがコード・出力と対応しない = 3、図とコードが揃い、ラベル・数値が一致 = 5（max_code_run が大きいのに図が少ない時は注意）
- 作者らしさ: debimate-visual-notes の書き方（です・ます、太字なし、冒頭の型、「本記事では」の前の <br>、図の caption）に沿っているか。利点・欠点の節の有無はここでは見ない（テンプレ感と逆向きに働くため）

- テンプレ感（1〜5、5 = テンプレ感が無い）: 題材に関係なく「必要な理由 → 仕組み → 利点 → 欠点 → 効果が小さいケース」の型をなぞっているだけか。読者が最初に知りたい問いの順に構成されているか（著者: Wallet が良いのは、最初に知りたい内容を箇条書きで挙げてから書き、競合との比較を明確に示したから。古い create-tech-notes で書いたノートはテンプレ感が強いはず）
- 比較（1〜5、該当なしも可）: 代わりの手段・競合・似た仕組みとの違いが、表・図・実験で明確に示されているか

- 読者の場面（1〜3）: 冒頭が「その技術を使おうとしている人」か「既存のシステムで出会った人」の場面から入るか。1 = 定義から入る、2 = 一般的な場面、3 = 具体的に困る場面
- 結び（1〜3）: 結びが、冒頭の読者の次の判断（使うか・やめるか・何を確かめるか）で閉じるか。1 = 利点・欠点・効果が小さいケースの型（節名を「得られる性質」「制約」などに変えただけのものも含む）が一般論のまま、2 = 型だが本文の実験・事例を受けて次の判断を渡す、3 = 型を使わず、冒頭の場面に答えて閉じる（著者: create-tech-notes 時代のノートは最後の流れが強引）
- 想定の読者は、関連性・読者の場面・結びで揃える。セクションの題材の利用者（ブロックチェーンならウォレットや取引を扱う開発者、DB ならアプリから DB を使う開発者）とする。ML のノート（projects/ml/notes、/ml/ 配下）は、ML を学び始めたエンジニアと、scikit-learn などで手元のデータに使う人とする。数学（ml-math）は、ML の説明で出てきた式や指標を自分で計算して確かめたい人とする
