# 関連記事の計算

`related_posts_index.html` がシリーズ・タグ・カテゴリ・セクションからページへの
逆引き索引を作り、`partialCached` で同じビルド内で共有する。
各ページは得点の付く候補だけを取り出すため、無関係な週報を毎回比較しない。
索引はHugoのメモリ内に保持し、ブラウザに配信するファイルや外部依存は追加しない。

採点は従来どおりシリーズ100、タグ20、カテゴリ8、同じセクション3。
重複する値は一度だけ数え、同点なら公開日の近さ、さらに同点なら元のページ順を使う。
タグの大文字小文字も従来どおり区別する。

## 検証

2026-11-01、Hugo 0.166.0で、変更前後のサイト生成物6,030ファイルが完全一致した。
比較時は画像キャッシュを使い、`--clock 2026-11-01T12:00:00+09:00`で時刻を固定した。
テンプレート計測で関連記事の累計時間は約9.6秒から約6.8秒となった。
これは並列実行の累計であり、ビルド全体の短縮時間ではない。

別の模擬サイトでは記事229件・ノート121件を固定し、タグのない週報を増やした。
実際の関連記事テンプレートをホームから350回呼び、記事本文・画像の生成を省いた。
GOMAXPROCS=2、各条件3回のプロセス実行時間の中央値:

| 週報数 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 17 | 4.59秒 | 2.75秒 |
| 1,560（52週×30年） | 13.09秒 | 2.73秒 |

模擬サイトでも変更前後の関連記事HTMLは一致した。
この数値は本番サイト全体の30年後のビルド時間の予測ではない。
記事そのものや共通タグの付いたページが増えると、比較対象は引き続き増える。

`scripts/test_related_posts.py` は小さなサイトをHugoで生成し、採点・同点・日付差・
値の重複・大文字小文字・無関係なページ追加後の結果を独立した計算で検証する。
既存CIの unittest discovery で実行される。

```sh
python3 -m unittest discover -s scripts -p test_related_posts.py
```

ローカルでHugoを指定する場合は `HUGO=/path/to/hugo` を設定する。
