# 週報一覧の画像

週報にはこれまでどおり元画像を配置するだけでよい。サムネイルの手作業での作成や、追加コマンドの実行は不要。通常の Hugo ビルド（ローカル・GitHub Actions 共通）で自動生成する。

トップの週報カードと `/weeknotes/` の各ページでは、話題の画像から幅360・540・720pxのWebPを生成し、`srcset` と `sizes` でブラウザーに選択させる。スクロールで追加するカードも同じ処理を使う。元画像より大きな解像度には拡大しない。一覧用の圧縮品質は65で、GIF・WebPのアニメーションを維持する。再圧縮のため画質が完全に同一になるわけではない。

元画像より容量が増える候補は除外する。小さい候補が残っていれば、それらだけを配信し、高密度画面でも重い元画像に戻さない。すべての候補が元画像以上の容量になる場合は元画像を使う。

本文・年間ページの画像配信設定と元画像ファイルは変更しない。トップの週報カードと週報一覧の先頭以外のカードは `loading="lazy"` を使い、画面から遠いカードの画像取得を遅らせる。

実装は `layouts/partials/weeknotes/image_delivery.html` の `thumbnail` オプションと、`layouts/weeknotes/list.html`、`layouts/partials/home_weeknote_card.html`。トップと週報一覧で生成画像を共用し、本文とはキャッシュキーを分けている。

Gamesの動画をトップと週報一覧の特定カードで使う場合は、週報のfront matterの `cardGames` に「話題の見出し: Gamesのname」を指定する。両方の一覧で同じ選出処理を使い、Gamesと同じ動画・ポスターを参照する。画面内で自動再生、画面外で停止し、スクロールで追加されたカードにも適用する。本文は次のショートコードで指定する。

本文でも同じ動画を使う場合は `{{< game-demo "Succubus Live" >}}` を配置する。週ページ・話題ページ・年間ページで再生でき、年間ページへの追加読み込みにも対応する。

検証は `make lint-links`。アニメーションの変更時には、元画像と生成画像をデコードし、動き・総再生時間・ループ設定も確認する。同じ絵の連続フレームが統合される場合があるため、フレーム数だけで再生内容の欠落を判断しない。
