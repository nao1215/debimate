# ローカル実験

Python 3（標準ライブラリだけ）で動きます。2026-11-17 に Python 3.14.4 で実行しました。

```sh
python3 experiment.py > output.txt
```

`experiment.py` は 10 万個のキー（`user:0` から `user:99999`）を次の方法で振り分け、キーの保存先が変わった割合と、各サーバーが持つ割合を数えます。データの転送や時間は測っていません。キーとサーバー名の位置は MD5 の先頭 8 バイトで決め、乱数のシードは固定しているので、何度実行しても同じ数字が出ます。

1. 3 台から 4 台に足す（台数で割る、リングに 1 台 1 点、1 台 100 点）
2. サーバー名を変えて 1,000 回（1 台 1 点、弧の長さで計算）
3. 10 台で、1 台あたりの点の数ごとの偏り（200 回ずつ）
4. 4 台から cache-2 を外した時に、そのキーを引き継ぐサーバー
5. 時計回りの次の 3 点に複製を置いた時に、同じサーバーへ重なる割合
6. 要求の数が Zipf 分布（s = 1）に従う時の、サーバーごとの要求の割合
7. Jump Consistent Hash・Rendezvous・Maglev との比較
8. 組み込みの `hash()` がプロセスごとに違う値を返すこと

`output.txt` は 2026-11-17 に実行した結果です。`results.json` は同じ結果を図の生成に使う形で書き出したものです。
